### P13：五个案例，一个规律

**横向对比**：

| 维度 | 黄天赐 | 王桂平 | 刘力 | 王佳男 | 吴迪 | 规律 |
|------|------|------|------|------|------|------|
| 系统规模 | 16 页 | 33 页 | 29 页 | 19 页 | 1 页 | **不拼规模拼价值** |
| AI 耗时 | 1 周 | 半天 | 1 周 | 数天 | 碎片 | **以"天"为单位** |
| 传统 | 2 人月 | 3-6 人月 | 3+ 人月 | 6 人月 | 1-2 周 | **压缩 10-100 倍** |
| 人数 | 1 人 | 1 人 | 1 人 | 1 人 | 1 人 | **一个人 = 一个团队** |
| 主业 → AI补了什么 | 前端 → 后端 | 后端 → 前端 | 产品 → 开发 | 商务 → 全部 | 总工 → 开发 | **角色边界融化** |

**四个核心洞察**：

1. **时间被压缩了一个数量级**：从"月"到"天"到"小时"。不是效率提升，是维度跃迁。
2. **一个人就是一个团队**：五个系统合计 98 个视图页面，全部一人完成。
3. **角色边界被 AI 融化了**：王桂平（后端）补前端，黄天赐（前端）补后端，刘力（产品经理）补开发，王佳男（商务经理）补全部技术。**每个人原来都缺某个角色能力，AI 把缺口填上了。**
4. **总工也在写代码**：吴迪（总工）既催化了王桂平的评标系统诞生，自己也用 AI 写出了云控恒进水务监控大屏——1095 行纯前端，4 台泵实时数据，AI 权重优化引擎。连总工都在亲手干了。

**核心公式**：
```
你的 AI 价值 = 你的专业领域知识 × AI 工具使用能力
```

> "最懂业务的人，现在最懂 AI。"
> "AI 赋能就三步——辅助、替代、创造不可能。"
> "半年时间，从'跟 AI 聊天'进化到'用 AI 建系统、拿项目、拓边界'。"

### P15：AI 做了 60 年，为什么最近三年才爆发？

**AI 简史（只讲关键节点）**：

```
1950s-2010s：传统 AI
├─ 专家系统 → 机器学习 → 深度学习
├─ 能做的：人脸识别、安全帽检测、设备预测、推荐算法
├─ 不能做的：听懂人话、写文章、理解上下文
└─ 你们工地上已经在用的：安全帽识别摄像头 = 传统 AI

2017：转折点——Transformer 诞生（Google）
├─ 《Attention is All You Need》论文发表
├─ "注意力机制"：机器第一次能同时理解一句话里的所有词
└─ 为 LLM 铺平了路，但此时还停留在实验室

2022.11：第一次实用爆发——ChatGPT 3.5（OpenAI）
├─ 2 个月 1 亿用户，人类历史上增长最快产品
├─ 第一次让普通人觉得"AI 能和我聊天"
├─ 这是 Transformer 架构的第一次大规模应用落地
└─ 从此 AI 从实验室走进了办公室

2023-2026：大爆炸
├─ GPT-4 / Claude / DeepSeek / Kimi / Qwen → 模型井喷
├─ 多模态 → 不仅能聊，还能看图、听语音
├─ Agent → 从"会说话"到"会干活"
└─ 推理模型（DeepSeek-R1、o3）→ 不是直接回答，先思考再开口
```

> "AI 不是新东西，但 LLM 是。传统 AI 能识别人脸；LLM 能理解你心里想什么。我们要讲的，就是 LLM 这条线。"

### P18：LLM 怎么干活？——四种工作模式

├─ 适用场景：写公文、查政策、学新知识、辅助决策
├─ 成熟度：已全民普及
└─ "这是所有 AI 的起点，也是你最常用的方式。"

② Copilot 模式——"你做你的事，AI 在旁边实时帮忙"
├─ 嵌在你现有工作软件里，不需要额外打开

├─ 成熟度：已大规模落地
└─ "不用离开你正在用的软件，AI 就在旁边。"

③ Agent 模式——"你给目标，AI 自己去干"
├─ 告诉 AI 一个目标，它自己规划步骤、调用工具、交付结果
├─ Agent 工具/平台：
│   ├─ Claude Code：说"重构这个模块"，AI 自动读代码→改文件→跑测试
│   ├─ Manus / Cursor / Trae：AI 编程环境，AI 主导、人审核

│   ├─ 中铁建设"铁小智"：90 秒审完 22 万㎡ 高铁站房方案
│   └─ 南方电网倒闸操作机器人：一键分解任务→自动执行
├─ AI 自主程度：★★★☆☆（AI 执行，人监督）
├─ 适用场景：多步流程自动化——招投标、合同审查、档案管理
├─ 成熟度：正在快速成熟
└─ "大模型给你答案，Agent 给你结果。"

④ Multi-Agent 模式——"你给目标，一群 AI 协作完成"
├─ 主 Agent 拆解任务→派给多个子 Agent 并行执行→汇总结果
├─ 为什么需要？一个 AI 有上下文限制，多个 AI 各管一摊、并行推进
├─ 业界定义（来源：Anthropic 官方 + arXiv 综述 2412.17481）：
│   Multiple LLM-driven agents autonomously using tools in a loop, working together
├─ 已经落地的产品：
│   ├─ Anthropic Claude Research：多 Agent 系统比单 Agent 研究能力提升 90.2%
│   ├─ Claude Code SubAgent：主 Agent 自动 spawn 子 Agent 各查一部分代码
│   ├─ Kimi 集群模式：复杂任务自动并行分拆，多子 Agent 协同
│   └─ 南方电网大瓦特：巡检 Agent ↔ 调度 Agent ↔ 维修 Agent 协同

│   ├─ 简单委托：主 Agent 派活→子 Agent 干完汇报（Claude Code SubAgent）
│   ├─ 编排协作：主 Agent 规划→并行派活→决策是否继续（Anthropic Research）

│   └─ 团队作战：各有角色（设计/开发/测试），共享上下文（Claude Code Agent Teams）
├─ AI 自主程度：★★★★☆（AI 协作，人监督）
├─ 适用场景：复杂调研、多维度分析、跨系统协同
└─ "你派一个人调研 vs 派一个小组调研——效果不一样。AI 也一样。"

**三个关键判断**：

1. 大部分企业对 AI 的想象停在"辅助"——提高效率、减少错误。这没错，**但只是起点**。

> "AI 赋能就三步——辅助、替代、创造不可能。你在哪一步？下一步往哪走？"

**五大避坑指南**：

| # | 坑 | 避坑策略 |
|:---|:---|:---|
| ① | **问题定义不清**——利益相关者经常误传要用AI解决什么问题 | 先把"到底要解决什么"写在一页纸上，让业务和技术都签字确认 |

| **业务应用** | 无应用 | 个别场景试点 | 多场景扩展 | 深度整合核心流程 | 驱动业务模式创新 |

### P45：国产大模型选型完全指南（含决策树）

**决策树——先问自己一个问题**：
```
是否需要私有化部署？
├── 是 → 信创要求极高 → 华为盘古+昇腾
│        需要丰富生态 → 文心一言+千帆平台
│        成本敏感+开源 → DeepSeek+自研运维
└── 否 → 阿里云生态 → 通义千问API
         多模型需求 → OneAPI统一网关
```

**完整对比表**：

| 模型 | 部署方式 | 核心优势 | 适用场景 | 等保/合规 | 生态 |
|-----|---------|---------|---------|----------|------|
| **DeepSeek** | 本地化/专有云/混合云 | 开源免费，成本可控；响应延迟<0.5秒 | 智能客服、知识库问答、代码辅助 | 需自评 | 开源社区 |
| **文心一言** | 公有云API / 私有化部署 | 百度智能云千帆平台；PaddleSlim量化压缩 | 金融合同审查、军工质检、智能制造 | 等保三级+GDPR | 百度生态 |
| **通义千问** | 阿里云API / 专有云 / 私有化 | 钉钉/阿里云深度集成；长文本128K上下文 | 办公协同、长文档处理、营销文案 | 阿里云合规 | 阿里生态 |
| **华为盘古** | 华为云 / 私有化 / 边缘部署 | 全栈国产化；行业大模型（政务、金融、制造） | 政务公文、涉密场景、信创要求极高场景 | 等保三级 | 华为生态 |

**私有化部署 vs 公有云 API——怎么选**：

| 对比项 | 私有化部署 | 公有云API调用 |
|:---|:---|:---|
| **数据安全** | 数据不出域 | 依赖加密传输 |
| **响应延迟** | <50ms（局域网） | 50-300ms（受公网影响） |
| **初始成本** | 高（GPU服务器+授权） | 低（按量计费） |
| **运维复杂度** | 高（需专业AI运维团队） | 低（厂商负责维护） |
| **适用企业** | 金融、医疗、军工、政府等强监管行业 | 中小企业、非核心业务场景 |
