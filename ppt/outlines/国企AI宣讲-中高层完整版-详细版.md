**详细内容要点**：
—— 2020年首次系统部署国企数字化转型，要求制定总体规划和路线图
—— 2023年将AI列为央企战略性新兴产业重要方向

### P5：央企AI考核指标体系
- 研发投入：AI相关研发经费投入强度
- 场景落地：AI技术在核心业务场景的应用数量和覆盖率
- 数字化程度：业务流程数字化覆盖率、数据共享率
- 人才建设：AI领域专业人才引进和培养情况
- 创新成效：AI相关专利、标准、成果转化情况
- 数据治理：数据资产管理和数据治理能力
- 配图建议：六角雷达图

**详细内容要点**：
—— 考核维度详解（来源：[[wiki/synthesis/国企AI宣讲-政策锚定]] §2.2）：
  | 考核维度 | 具体指标 | 说明 |
  |:---|:---|:---|
  | **研发投入** | AI相关研发经费投入强度 | 衡量企业对AI的投入力度 |
  | **场景落地** | AI技术在核心业务场景的应用数量和覆盖率 | 衡量AI的落地深度 |
  | **数字化程度** | 业务流程数字化覆盖率、数据共享率 | 量化数字化转型进展 |
  | **人才建设** | AI领域专业人才引进和培养情况 | 人才储备指标 |
  | **创新成效** | AI相关专利、标准、成果转化情况 | 创新产出指标 |
  | **数据治理** | 数据资产管理和数据治理能力 | 数据基础设施水平 |
—— 差异化考核设计：职能部门重"应用成效"，生产部门重"数字化率"，技术部门重"自主创新"
—— 探索中的新指标：代表建议设立国企"科技创新专项考核"；将AI研发与应用成果作为企业负责人任期考核的重要内容；探索建立"新质生产力发展指数"
—— 数字化转型目标：2025年央企数字化转型取得显著成效；"十五五"末力争整体数字化率达到80%以上（以中国海油为标杆）

### P8：AI 做了 60 年，为什么最近三年才爆发？

> **核心信息**：传统 AI（人脸识别、安全帽检测、推荐算法）已经做了几十年，但一直局限在"只做一件事"。LLM 改变了游戏规则——一个模型能做无穷多种事。

**AI 简史（只讲关键节点）**：

```
1950s-2010s：传统 AI
├─ 专家系统 → 机器学习 → 深度学习
├─ 能做的：人脸识别、安全帽检测、设备预测、推荐算法
├─ 不能做的：听懂人话、写文章、理解上下文
└─ 你们工地上已经在用的：安全帽识别摄像头 = 传统 AI

2017：转折点——Transformer 诞生（Google）
├─ 《Attention is All You Need》论文发表
├─ "注意力机制"：机器第一次能同时理解一句话里的所有词
└─ 为 LLM 铺平了路，但此时还停留在实验室

2022.11：第一次实用爆发——ChatGPT 3.5（OpenAI）
├─ 2 个月 1 亿用户，人类历史上增长最快产品
├─ 第一次让普通人觉得"AI 能和我聊天"
├─ 这是 Transformer 架构的第一次大规模应用落地
└─ 从此 AI 从实验室走进了办公室

2023-2026：大爆炸
├─ GPT-4 / Claude / DeepSeek / Kimi / Qwen → 模型井喷
├─ 多模态 → 不仅能聊，还能看图、听语音
├─ Agent → 从"会说话"到"会干活"
└─ 推理模型（DeepSeek-R1、o3）→ 不是直接回答，先思考再开口
```

**金句**："AI 不是新东西，但 LLM 是。传统 AI 能识别人脸；LLM 能理解你心里想什么。我们要讲的，就是 LLM 这条线。"

### P10：从"只会说话"到"能看会听"——LLM 的四种能力升级

> **核心信息**：LLM 不只是文字对话。从 2023 到 2026 年，它在四个方向上大幅扩展了能力边界。

**LLM 为什么突然能"看"图了？**

> 不是 LLM 长了眼睛。而是：把图像切成小方块 → 每方块转成一串数字（类似文字的 token）→ LLM 用处理文字的同一套机制来"读"图像。就像你大脑把所有信息都翻译成同一种语言来理解——LLM 把图像、语音、文字都转成同一种"AI 语"。

```
① 多模态——从"读文字"到"看图纸、听语音、读表格"
├─ GPT-4V、Claude 3：能看懂施工现场照片
├─ 云筑网图像文本解析：准确率 99.7%
├─ WPS AI：读 PDF、分析图表、生成摘要
└─ 建筑行业的图纸、报表、现场照片，AI 都能"读"了

② 工具调用——从"只会说"到"能操作软件"
├─ 本质：让 LLM 学会调用外部 API——查数据库、发邮件、填表单
├─ 南方电网大瓦特：AI 直接调用开关柜接口，完成倒闸操作
├─ Claude Code：AI 自主读取代码文件、调用命令行、运行测试
└─ AI 从"写作工具"变成"操作工具"

③ 企业知识库——从"懂全世界"到"懂你们公司"
├─ 把企业制度、合同、项目资料结构化存储
├─ 国家电网：1829 项技术标准数字化，检索到"条款级"
├─ 中建五局：制度问答，新人不用问同事
└─ 注意：RAG 只是实现这个的技术手段之一，不是独立概念

④ 推理能力——从"直接回答"到"先想再说"
├─ 以前的 LLM：你问 → AI 凭直觉回答
├─ 现在的推理模型（DeepSeek-R1、OpenAI o3）：
│   你问 → 拆解问题 → 多步推理 → 自我检查 → 给出答案
└─ 复杂决策开始可行：合同审查、投资评估、方案比选
```

### P11：LLM 怎么干活？——四种工作模式

> **核心信息**：同一个 LLM，用起来有四种完全不同的"姿势"。从被动到主动，从辅助到自主。对国企来说，关键是**选对级别**——不要所有场景都追 Agent，很多场景 Chat 就够了。

```
① Chat 模式——"你问，我答"
├─ 打开聊天窗口，打字提问
├─ 豆包、Kimi、文心一言、DeepSeek、ChatGPT、Claude
├─ 能做的：回答问题、写文档、总结、翻译、头脑风暴
├─ 不能做的：操作你的软件、访问你的邮箱、走流程
├─ AI 自主程度：★☆☆☆☆（人在主导）
├─ 适用场景：写公文、查政策、学新知识、辅助决策
├─ 成熟度：已全民普及
└─ 金句："这是所有 AI 的起点，也是你最常用的方式。"

② Copilot 模式——"你做你的事，AI 在旁边实时帮忙"
├─ 嵌在你现有工作软件里，不需要额外打开
├─ WPS AI / Office Copilot：写文档时帮你改措辞、排版
├─ 通义听悟：开着会，AI 实时转录 + 总结，30 分钟纪要变 5 分钟
├─ GitHub Copilot / Cursor：程序员写代码，AI 实时补全
├─ AI 自主程度：★★☆☆☆（人主导，AI 实时辅助）
├─ 适用场景：日常办公提效——写 PPT、做表格、开会议纪要
├─ 成熟度：已大规模落地
└─ 金句："不用离开你正在用的软件，AI 就在旁边。"

③ Agent 模式——"你给目标，AI 自己去干"
├─ 告诉 AI 一个目标，它自己规划步骤、调用工具、交付结果
├─ Agent 工具/平台：
│   ├─ Claude Code：说"重构这个模块"，AI 自动读代码→改文件→跑测试
│   ├─ Manus / Cursor / Trae：AI 编程环境，AI 主导、人审核
│   ├─ WorkBuddy：无代码拖拽搭建"审发票→填报销→发审批"自动化流程
│   ├─ Lobster（中建智能）：AI 助手，有手脚能干活
│   └─ Hermes（中建智能）：AI 助手，能力更强、有成长性
├─ Agent 驱动的企业应用：
│   ├─ 云筑网云智采：自动资审→智能评标→自动开定标，采购周期缩短 40%
│   ├─ 中铁建设"铁小智"：90 秒审完 22 万㎡ 高铁站房方案
│   └─ 南方电网倒闸操作机器人：一键分解任务→自动执行
├─ AI 自主程度：★★★☆☆（AI 执行，人监督）
├─ 适用场景：多步流程自动化——招投标、合同审查、档案管理
├─ 成熟度：正在快速成熟
└─ 金句："大模型给你答案，Agent 给你结果。"

④ Multi-Agent 模式——"你给目标，一群 AI 协作完成"
├─ 主 Agent 拆解任务→派给多个子 Agent 并行执行→汇总结果
├─ 为什么需要？一个 AI 有上下文限制，多个 AI 各管一摊、并行推进
├─ 业界定义（来源：Anthropic 官方 + arXiv 综述 2412.17481）：
│   Multiple LLM-driven agents autonomously using tools in a loop, working together
├─ 已经落地的产品：
│   ├─ Anthropic Claude Research：多 Agent 系统比单 Agent 研究能力提升 90.2%
│   ├─ Claude Code SubAgent：主 Agent 自动 spawn 子 Agent 各查一部分代码
│   ├─ Kimi 集群模式：复杂任务自动并行分拆，多子 Agent 协同
│   └─ 南方电网大瓦特：巡检 Agent ↔ 调度 Agent ↔ 维修 Agent 协同
├─ 四种协作形态（从简单到复杂）：
│   ├─ 简单委托：主 Agent 派活→子 Agent 干完汇报（Claude Code SubAgent）
│   ├─ 编排协作：主 Agent 规划→并行派活→决策是否继续（Anthropic Research）
│   ├─ 对等协作：多 Agent 地位平等，自由通信协商（AutoGen Group Chat）
│   └─ 团队作战：各有角色（设计/开发/测试），共享上下文（Claude Code Agent Teams）
├─ AI 自主程度：★★★★☆（AI 协作，人监督）
├─ 适用场景：复杂调研、多维度分析、跨系统协同
└─ 金句："你派一个人调研 vs 派一个小组调研——效果不一样。AI 也一样。"
```

**四种模式一页总览**：

| | Chat | Copilot | Agent | Multi-Agent |
|--|------|---------|-------|-------------|
| 谁主导 | 人 | 人主导，AI 辅助 | AI 执行，人监督 | AI 协作，人监督 |
| AI 做什么 | 回答文字 | 实时辅助修改 | 自主多步执行 | 分工+并行+协调 |
| 代表 | 豆包/Kimi/DeepSeek | WPS AI/Office/通义听悟 | Claude Code/Manus/云智采 | Claude Research/Kimi集群 |
| 自主度 | ★☆☆☆☆ | ★★☆☆☆ | ★★★☆☆ | ★★★★☆ |
| 成熟度 | 全民普及 | 大规模落地 | 快速成熟 | 已可用，高价值场景 |

### P24：Part 3 收束——AI 赋能的三级跃迁：辅助 → 替代 → 创造不可能

```
第二层：算法平台层 → 模型资产集中化治理
第一层：基础设施层 → 算力资源底层支撑
```
- **关键设计思想**：IT与业务直接对话、ROI驱动、模型资产化
- 案例：美的物料排产从10小时→1小时

**详细内容要点**：
—— 美的四层架构详解（来源：[[wiki/synthesis/AI落地路径]] §框架一）：
  | 层级 | 名称 | 核心功能 | 谁负责 |
  |------|------|---------|--------|
  | **第一层** | 基础设施层 | 算力、云资源、存储、网络 | IT/云平台团队 |
  | **第二层** | 算法平台层 | 模型训练、部署、管理、复用 | AI研究院/算法团队 |
  | **第三层** | 应用集成层 | API封装、低代码工具、业务系统对接 | 平台产品团队 |
  | **第四层** | 业务应用层 | 各事业部/职能部门的具体AI应用 | 业务部门+IT经理 |
—— 关键设计思想：
  1. IT与业务直接对话：传统模式（业务→IT需求→外包开发→交付，层层衰减）vs 美的模式（IT经理驻场事业部，需求直接转化为应用）
  2. ROI驱动：每个AI项目必须有明确的投入产出测算。案例：美的自研物料计划优化算法，将195万种物料的排产计算从10小时缩短到1小时，效率提升90%
  3. 模型资产化：不是每个项目都从零训练模型，共性能力沉淀到算法平台层，供上层复用
—— 对央企的启示：
  | 央企常见痛点 | 美的四层架构的解法 |
  |-------------|-------------------|
  | 业务和IT"两张皮" | 第四层让IT经理直接对接业务 |
  | 重复造轮子 | 第二层统一算法平台，模型复用 |
  | AI项目算不过账 | 强制ROI评估，用效率提升说话 |
  | 业务部门不会用AI | 第三层提供标准化工具，降低门槛 |

  | **生成内容（AIGC）权属争议** | AI生成内容是否构成"作品"、版权归属于谁 | 北京互联网法院典型案例 |
  | **输出内容实质性相似** | 生成内容与他人作品高度雷同，构成侵权 | 2025年AIGC合规白皮书 |
  | **商业秘密泄露** | 员工将企业专有信息输入公共AI工具 | GitLab调查：79%企业担忧 |
—— 三级过滤合规机制：
  - 一级预防（输入层）：数据来源合规审查，优先选择通过国家网信办备案的AI工具
  - 二级过滤（预处理层）：部署版权感知过滤系统（数字指纹、水印检测）
  - 三级阻断（输出层）：设置"独创性阈值"（建议相似度不高于70%），高风险领域强制人工审核
—— AI项目成功落地的"五要五不要"：
  | 五要 | 五不要 |
  |:---|:---|
  | 要从业务痛点出发，而非技术热点 | 不要为了AI而AI，盲目追大模型 |
  | 要先治理数据，再训练模型 | 不要忽视数据质量 |
  | 要选择容错率高的场景先行试点 | 不要在核心系统直接全面替代人工 |
  | 要建立动态供应商管理和退出机制 | 不要与单一供应商深度绑定 |
  | 要落实合规审计和全链路日志 | 不要等出事了才补合规课 |

### P34：国产大模型选型决策树
```
是否需要私有化部署？
├── 是 → 信创要求极高 → 华为盘古+昇腾
│        需要丰富生态 → 文心一言+千帆平台
│        成本敏感+开源 → DeepSeek+自研运维
└── 否 → 阿里云生态 → 通义千问API
         多模型需求 → OneAPI统一网关
```
- 私有化 vs 公有云对比表
- 五要五不要

**详细内容要点**：
—— 主流国产大模型企业部署对比（来源：[[wiki/synthesis/国企AI宣讲-风险合规]] §2.1）：
  | 模型 | 部署方式 | 核心优势 | 适用场景 |
  |-----|---------|---------|---------|
  | **DeepSeek** | 本地化/专有云/混合云 | 开源免费，成本可控；响应延迟<0.5秒 | 智能客服、知识库问答、代码辅助 |
  | **文心一言** | 公有云API / 私有化部署 | 百度智能云千帆平台；等保三级+GDPR；PaddleSlim量化压缩 | 金融合同审查、军工质检、智能制造 |
  | **通义千问** | 阿里云API / 专有云 / 私有化 | 钉钉/阿里云深度集成；长文本128K上下文；代码生成 | 办公协同、长文档处理、营销文案 |
  | **华为盘古** | 华为云 / 私有化 / 边缘部署 | 全栈国产化；行业大模型（政务、金融、制造） | 政务公文、涉密场景、信创要求极高场景 |
—— 私有化部署 vs 公有云API对比：
  | 对比项 | 私有化部署 | 公有云API调用 |
  |:---|:---|:---|
  | **数据安全** | 数据不出域 | 依赖加密传输 |
  | **响应延迟** | <50ms（局域网） | 50-300ms（受公网影响） |
  | **初始成本** | 高（GPU服务器+授权） | 低（按量计费） |
  | **运维复杂度** | 高（需专业AI运维团队） | 低（厂商负责维护） |
  | **适用企业** | 金融、医疗、军工、政府等强监管行业 | 中小企业、非核心业务场景 |
—— 供应商选择策略（避免锁定、保持开放）：
  - 普华永道建议：动态供应商资源池管理——通过"中台化+低代码"技术支持灵活配置
  - 案例：招商局集团将20家二级公司、近3000家下属企业的采购统一平台管理，同时支持下属企业快速配置匹配业务需求的管理模块
  - 避免供应商锁定的技术架构：
    | 层级 | 锁定风险 | 开放架构解决方案 |
    |------|---------|--------------|
    | **计算层** | 绑定特定实例类型 | **容器化** (Docker + Kubernetes) |
    | **存储层** | 绑定专有存储API | **S3兼容接口/抽象存储层** |
    | **数据库** | 绑定专有DB引擎 | **开源数据库** + 跨云复制 |
    | **AI模型层** | 绑定单一LLM供应商 | **多模型抽象层** + 私有模型 |

> 来源：[[wiki/synthesis/国企AI宣讲-风险合规]] §2.3 + §六

  | 阶段 | 时间 | 关键动作 |

  | **试点运行** | 30-60天 | 启动1-2个轻量化AI场景试点，完成数据对接、模型部署；验证业务价值，收集反馈，优化模型与流程 |
  | **优化推广** | 60-90天 | 总结试点经验，形成标准化模板；制定扩展计划，启动第二批场景复制 |
—— AI试点项目通用实施流程：
  ```
  1. 项目立项 → 明确目标、范围、时间、预算
        ↓
  2. 资源准备 → 人力、物力、财力、监控计划、风险管理
        ↓
  3. 试点实施 → 按计划执行，数据收集分析，及时调整改进
        ↓
  4. 评估总结 → 可行性评估、效果评估，形成决策参考
        ↓
  5. 推广复制 → 经验推广，根据实际情况调整优化
  ```
—— 试点项目评估维度：
  | 评估维度 | 核心指标 | 评估方法 |
  |:---|:---|:---|
  | **业务效果** | 效率提升、质量改善、成本降低 | 对比试点前后数据 |
  | **技术性能** | 任务完成准确性、处理速度、系统稳定性 | 技术测试、压力测试 |
  | **成本效益** | 许可费用、基础设施、运营成本、ROI | 投资回报率和回报周期计算 |
  | **风险控制** | 数据安全、伦理合规、隐私保护 | 风险评估与缓解策略审查 |
  | **用户反馈** | 满意度、使用体验、改进建议 | 问卷调查、访谈 |
  | **战略一致性** | 与组织战略目标匹配度 | 高层评估 |
  | **扩展潜力** | 可复制性、可推广性 | 评估是否能扩展到其他相邻业务场景 |
—— 快速见效的Quick Wins建议：

  - 第4-6个月：形成内部最佳实践，启动规模化培训
