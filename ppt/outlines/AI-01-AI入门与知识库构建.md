## 阶段一：窗口依赖期（3月以前）

### 第 6 页：阶段初期的使用方式

- **标题**：起步阶段——把AI当作"高级搜索引擎"
- **内容**：
  - 偶尔打开网页版ChatGPT或Kimi：提问 → 复制答案 → 粘贴到文档
  - 主要用途：
    - 生成文本素材 → 手动修改 → 使用
    - 上传PDF → 获取摘要 → 关闭
  - 用完即弃，每次对话都是孤立的
  - 当时的认知：AI≈增强版百度，尚未意识到范式差异

### 第 7 页：网页聊天的结构性局限

- **标题**：轻度使用中遇到的几个问题
- **内容**：
  - 上下文窗口有限——对话稍长就需要开启新会话
  - 会话隔离——AI无法跨对话关联信息
  - 知识无法积累——花费时间引导AI理解业务，下次对话全部重置
  - 输出缺乏针对性——AI不了解组织背景和业务特点，产出偏通用
  - **根本问题**：网页聊天模式本质上是为"一次性问答"设计的

### 第 8 页：阶段小结

- **标题**：窗口聊天的适用边界
- **内容**：
  - 适合场景：一次性任务——查资料、写文案、翻译、简单问答
  - 不适合场景：需要持续积累和深度思考的工作——项目管理、知识沉淀、跨文档分析
  - 当时并未意识到这是"范式"层面的问题，误以为AI的能力上限如此
  - 直到3月的一次体验，彻底改变了这个认知

### 第 10 页：第一次认知冲击

- **内容**：

  - **亲身测试**：10分钟，从空文件夹到可运行的界面应用
  - 作为早期程序员，清楚这个量级的含义——相当于半天的工作量
  - **冲击**：AI在"执行"层面已经远超个人效率上限
- **演讲备注**：讲出"震住"的感觉。24年的老手被10分钟的AI震住——这个反差才有冲击力。

### 第 11 页：信心阶段——从兴奋到冒险

- **标题**：信心膨胀——一个自然但危险的心理阶段

  - **关键认知**：没有这股暂时的"盲目乐观"，不会敢接后面的挑战性项目

### 第 12 页：实战案例——垃圾站智能体项目

- **标题**：第一个真实项目——垃圾中转站智能管理系统

### 第 13 页：第一阶段反思

    3. AI的辅助作用——将"专业度"在短时间内有效可视化
  - **第一课**：AI是放大器，不是魔术师。自身积累越厚，AI的放大效应越显著。没有根基，AI也无能为力

  - **决策**：尝试用AI工具"硬啃"陌生领域
- **配图建议**：悬崖边的小人

### 第 16 页：自动化工具的双面性

- **标题**："龙虾"（Laurent）的实践——效率与风险的博弈
- **内容**：
  - 龙虾（Laurent）是一套AI自动化工作流工具
  - 能力范围：信息搜索、日报生成、文件分发、数据整理
  - **正向体验**：自动完成复杂研究任务，产出质量出人意料
  - **负面体验**：同样的工作流，更换输入后输出完全偏离预期——且"自信满满"地给出错误结果
  - **核心矛盾**：AI自动化能力越强，失控的风险也越大

### 第 17 页：管理AI的方法论——"三省六部制"

- **标题**：应对AI不可控性的管理框架
- **内容**：
  - 面对工具失控，需要建立明确的管理机制
  - **"三省"**——三级检查节点：
    - 任务下发前确认（目标、边界、验收标准）
    - 执行过程中的中期检查（方向纠偏）
    - 交付后的质量审核（准确性、完整性）
  - **"六部"**——六个标准化流程模块：
    - 任务拆解、信息检索、分析推理、内容生成、质量审核、成果交付
  - **核心理念**：不是限制AI的能力，而是为其建立执行框架——类似给能力出众但经验不足的新人配备导师

### 第 18 页：第二阶段反思

- **标题**：AI是能力放大器，不是替代者
- **内容**：
  - **核心认知**：AI能大幅提升效率，但无法替代专业判断
  - AI能将专业能力放大10倍——前提是使用者具备该专业能力
  - AI能将工作效率提升10倍——前提是使用者能辨别结果的对错
  - **关键公式**：输出质量 = AI能力 × 使用者的管理能力
  - 管理、约束、审核——这是使用AI工具时不可跳过的基本功

### 第 20 页：转折点——需求的升级

  - 需求升级：从"能看的PPT"到"可交付的设计方案"
    - 需要讨论技术栈选型、系统架构设计、详细需求文档
  - 现有工具的局限性充分暴露：
    - 网页聊天：几十页文档，几轮对话后上下文断裂
    - 自动化工具：不可控的风险在工程化阶段不可接受
  - **结论**：需要一个"可靠、有记忆、可管控"的AI工作平台

### 第 21 页：解决方案——Claude Code + Obsidian

- **标题**：CC+OB——"不失忆"的AI工作平台
- **内容**：
  - **Claude Code**：具备文件系统操作能力的AI工具——不只是对话，能读写、整理、维护文件
  - **Obsidian**：本地化知识库载体——笔记数据完全存储在本地，结构化、可检索、可长期积累
  - **两者结合的价值**：
    - 持久记忆：今天输入的知识，明天仍可被AI调用
    - 完整上下文：所有讨论记录沉淀在知识库，每次交互基于完整历史
    - 可追溯：AI的产出可回溯到知识库中的原始素材
  - **与网页聊天的本质差异**：
    - 网页聊天：无状态、无记忆、每次从零开始
    - CC+OB：有状态、有记忆、持续积累

### 第 22 页：知识库搭建方法

- **标题**：知识库是"长出来"的，不是"设计出来"的
- **内容**：
  - 常见误区：花大量时间规划目录结构，却迟迟不开始
  - **建议路径**：从"乱"到"治"的渐进过程
  - **四步法**：
    1. 收集：将所有相关原始资料（文档、纪要、报告）集中存放
    2. 整理：借助AI工具自动分类、打标签、生成摘要
    3. 使用：基于知识库讨论方案、撰写文档、分析数据
    4. 维护：持续补充新资料、清理过时内容
  - **关键认知**：先开始积累，再逐步优化——不要在"准备阶段"消耗过多精力

### 第 23 页：AI辅助技术决策

- **标题**：AI在技术选型中的应用实践
- **内容**：
  - 在CC+OB框架下，团队与AI协作完成了技术方案的评估与决策
  - **交互方式**：向AI说明约束条件（团队规模、时间周期、预算限制）→ AI提供方案对比 → 团队拍板
  - **效果**：显著缩短了技术调研周期，快速收敛到适合的方案
  - **关键前提**：知识库保障了讨论的连续性——AI能记住之前的决策依据，不会每次都从头推理
- **演讲备注**：不是讲技术细节，是讲"怎么用AI做决策支持"。

### 第 24 页：能力边界的拓展

- **标题**：项目之外的收获——三个能力跃迁
- **内容**：
  - **① 看到即占有**
    - 发现优质开源项目 → 直接让AI拉取、运行、适配
    - 案例：vue-big-screen数据大屏（GitHub 804星）→ 填入真实数据 → 快速上线交互式大屏
  - **② 想到即实现**
    - 产生产品构思 → 不等程序员排期 → AI辅助快速原型
    - 案例：智能评标中心前端演示系统（10个页面），1天内完成
  - **③ 获知即学会**
    - 发现有用工具 → 立即安装试用 → 快速产出
    - 案例：huashu-design → 安装 → 5分钟生成企业官网全站
  - **底层逻辑**：这三个能力的核心不是AI本身，而是"领域知识 + 判断力 + AI执行力"的结合
- **演讲备注**：三个能力配三个真实案例。让在座感受到"看到→用到"的距离从以周计缩短到以分钟计。

### 第 25 页：第三阶段反思

- **标题**：能力边界的拓展公式
- **内容**：
  - **你的领域知识（知识库） × AI的执行力 = 你的超能力**
  - 知识库质量决定了产出的准确性——AI生成内容的可靠性取决于输入素材的质量
  - AI执行力决定了实现的效率——从想法到产出的周期缩短到原来的1/10
  - 缺失任何一方都会失衡：
    - 有知识无AI → 效率瓶颈，知识沉淀但无法快速转化
    - 有AI无知识 → 产出速度快但质量不可控，错误也被放大
- **配图建议**：公式大字

### 第 30 页：工具演进的思考

- **标题**：从工具到机器到AI——技术变革的三个层次
- **内容**：
  - **农业时代——工具增强体力**：工具是体力的延伸，提升的是"效率"
  - **工业时代——机器替代体力**：机器开始替代人的体力劳动，改变的是"就业结构"——旧岗位消失，新岗位诞生
  - **AI时代——算法替代脑力**：AI正在逐步替代认知劳动，不同于前两次——不是替代某个行业，而是渗透所有行业
  - **观察与判断**：
    - 积极面：每个人都能拥有AI助手，能力门槛持续降低
    - 挑战面：人类可能面临被"工具化"的风险——沦为AI在物理世界的执行终端
  - **应对思路**：保持学习，主动使用，同时守护不可替代的价值（判断力、经验、关系）

  - **一个判断框架**（源自李笑来的时间价值理论）：
    - 赚钱的本质是"出卖时间"，区别在于"一份时间卖几次"
    - 卖一次 → 打工；卖多次 → 写书、做课、做产品；卖别人的时间 → 创业
  - **反向思考**：能够"卖多次"的知识产品，必然经过了市场验证——能卖钱的课程，大概率有真实价值
  - **建议**：
    - 免费资源信息密度低、筛选成本高——你的时间比课程费用更值钱
    - 选课参考：GitHub高星项目、高销量课程——市场验证本身就是有效的筛选机制
    - 但最关键的不是"买什么"，而是**"买了立刻用"**——收藏等于吃灰
