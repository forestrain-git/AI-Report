## 二、行业预判（六模块）

### M1 拆解行业

**产业链图**

```
数据采集层                算法平台层               应用交付层              终端用户
BIM建模软件(Autodesk)  ──→ ALICE Technologies  ──→ 生成式排程SaaS  ──→ 总承包商/GC
智慧工地IoT传感器     ──→ nPlan(预测引擎)     ──→ 进度风险预测     ──→ 项目业主
无人机+360°摄像头     ──→ Buildots(视觉AI)    ──→ 现场进度追踪     ──→ 监理/咨询
ERP/采购系统数据      ──→ 广联达PMSmart       ──→ 物资-进度联动    ──→ 分包商
人工进度填报          ──→ Nodes & Links       ──→ 主动式进度Agent  ──→ 金融机构
```

**利润分配**（100元收入拆解）

| 环节 | 毛利率 | 说明 |
|:---|:---:|:---|
| 数据采集与接入 | 10-15% | BIM数据/IoT设备/人工填报，接口标准化成本高 |
| AI算法与模型 | 65-75% | 排程优化引擎+预测模型是核心壁垒，边际成本趋零 |
| 产品化与UX | 35-45% | SaaS可视化+移动端+API集成 |
| 销售与实施 | 20-30% | ToB销售周期长，需现场实施和培训 |

**关键控制节点**：**数据资产型 + 技术壁垒型** — 云筑网拥有10万亿交易数据（成本-工期关联）+ 1400万工人实名制数据（劳动力约束）+ 4100+智慧工地（实时进度验证），三者合一的数据维度全球竞品无人能及。同时，排程优化算法是第二控制节点。

**可优化环节**：建筑行业施工排程长期依赖人工经验（项目经理拍脑袋 + Excel/Project手动调整），缺乏系统性数据驱动的动态优化。现有工具（Primavera P6/MS Project）仅是"画图工具"而非"优化工具"。全球70%施工进度表存在严重缺陷（RHSS数据），AI替代空间巨大。

### M2 洞察变化

| 维度 | 变化 | 量级 | 证据 |
|:---|:---|:---:|:---|
| **新技术** | 大模型+运筹优化融合使AI排程从"辅助"走向"自动生成" | 🔴大 | ALICE生成数百万方案/分钟；nPlan训练75万项目数据；广联达斑马30分钟出计划 |
| **新技术** | 视觉AI+IoT实现实时进度自动采集，告别人工填报 | 🔴大 | Buildots 360°摄像头自动比对BIM；中铁盾构每秒2万条参数采集 |
| **需求侧** | 全球建筑业$1.6万亿生产力缺口，仅8.5%项目按时完工 | 🔴大 | McKinsey 2024数据；70%进度表存在严重缺陷（RHSS） |
| **需求侧** | 中国建筑业利润率持续走低（2024年行业平均利润仅2.86%） | 🔴大 | 精细化管理倒逼AI排程需求 |
| **供给侧** | ALICE/nPlan/Buildots已获商业验证，但均缺乏中国市场深耕 | 🟡中 | ALICE 2024年才进入亚太；nPlan 2025年进军北美中东亚太 |
| **政策法规** | 住建部智能建造试点城市+央企数字化转型考核 | 🟡中 | 智能建造试点扩大至30+城市 |
| **政策法规** | 日本"働き方改革"2024年生效，倒逼施工自动化 | 🟡中 | 鹿岛A4CSEL在日本加速推广 |

**判断**：这是一个**系统性变化** — 技术（大模型+运筹优化+视觉AI）+ 需求（建筑业生产力危机+利润率压力）+ 政策（智能建造试点+央企数字化考核）三重共振。变化量级足以支撑百亿级公司。

**与供应商风控方向的关键区别**：供应商风控的政策驱动力更强（"77号文"强制合规），而排程优化的市场需求驱动力更强（降本增效是内生需求）。排程优化更偏"效率工具"，需证明ROI才能驱动采购决策。

### M3 预判稳态B

**原子级需求拆解**

| 用户 | 场景 | 解决什么问题 | 愿付多少钱 |
|:---|:---|:---|:---|
| 中建各工程局项目经理 | 投标阶段进度方案编制 | 手动排程耗时长（2-3天→30分钟），方案比选靠经验 | 5-10万/年/项目 |
| 中建各工程局总工 | 施工阶段动态进度优化 | 进度滞后时不知如何调整资源最优 | 10-20万/年/项目 |
| 中建体系外的建筑央企 | 多项目资源跨项目调配 | 设备/人员闲置或短缺，缺乏全局最优调度 | 30-50万/年/企业 |
| 项目业主/代建方 | 进度风险预测与预警 | 无法提前预判哪些工序会延期 | 5-15万/年/项目 |
| 金融机构（银行/保险） | 工程项目贷后进度监控 | 项目延期导致贷款风险，缺乏独立验证手段 | 20-50万/年/机构 |

**稳态B推演**：

> （大模型+运筹优化技术成熟）→（使得AI从"画图工具"升级为"自动生成+动态优化"引擎）→（叠加建筑业利润率危机倒逼精细化管理）→ **施工排程从"项目经理经验驱动"转向"AI数据驱动+人工决策"，头部平台凭借独占数据资产和算法壁垒形成寡头格局。中国市场将由"掌握施工工序数据+劳动力数据+实时进度数据"的玩家主导。**

**中建发展在稳态B中的位置**：**数据资产层的独占者 + 场景入口的守门人**。云筑网的10万亿交易数据可构建"成本-工期-工序"关联矩阵（知道某项工序在不同项目中的实际耗时和成本分布），1400万工人数据可提供劳动力约束输入（知道哪些工种在哪些地区有多少可用资源），4100+智慧工地可提供实时进度反馈形成闭环。这三层数据的融合是ALICE/nPlan/广联达都无法做到的。

### M4 Timing

**周期定位**：**早期探索 → 爆发增长的过渡期**

- 全球AI排程市场已有ALICE/nPlan/Buildots等商业验证，但渗透率极低（<5%）
- 中国市场：广联达斑马进度计划以"工具"定位为主，距"AI自动排程引擎"有距离
- 中铁盾构AI排程在隧道领域领先，但高度垂直，不覆盖房建/市政/工业建筑
- 云筑网已有数据基础，但排程产品为零，需从零构建

**窗口期判断**：窗口已开，还有 **2-3 年**。原因：
- 广联达斑马进度计划2024-2025年加速AI化，若不尽快推出差异化产品，窗口将关闭
- 国际竞品（ALICE/nPlan）尚未深耕中国市场，但已在亚太布局
- 中建体系内部需求紧迫（利润率持续走低），内部验证窗口良好

**太早风险**：低 — 全球已有商业验证，不存在技术可行性问题
**太晚风险**：中高 — 广联达斑马进度已有先发优势和客户基础，新进入者需差异化突破

### M5 天花板大小

**四方法交叉验证**

| 方法 | 估算 | 说明 |
|:---|:---|:---|
| **直接数据** | 全球施工排程软件市场 $1.3-4.1B(2024)，2030年 $2.3-5.9B | 含传统+AI排程，年增速6-12% |
| **Top-down** | 中国建筑业总产值31万亿 × 软件支出占比0.1-0.3% = 31-93亿 | 中国建筑业软件渗透率远低于制造业 |
| **Bottom-up** | 中国大型施工企业500家 × 年均50万订阅 + 中型5000家 × 年均5万 = 5亿 | 仅SaaS订阅，不含定制实施 |
| **类比法** | 制造业APS（高级排程系统）全球市场 $2.6B(2025)，建筑业排程复杂度不低于制造业 | 建筑业排程更复杂（露天环境/多约束/天气影响） |

**结论**：AI施工排程中国市场可触达规模 **30-100亿元**，支撑十亿级体量公司。若叠加"方案自动生成"（从进度排程延伸到施工组织设计AI生成），天花板更高（可达200亿+）。

### M6 集中度

**现状**：**极其分散，无绝对头部**

- 全球层：ALICE/nPlan/Buildots/Nodes & Links 各有侧重，无一家独大
- 中国层：广联达斑马进度在工具层领先，但"AI自动排程引擎"无人占位
- 垂直层：中铁盾构AI在隧道领域领先但不跨领域

**趋势**：**C型（分散→集中）★ 最佳时机**
- 数据资产具有网络效应 — 排程数据越多，模型越准，客户越多
- 央企数字化转型考核将加速有"数据和场景"的玩家集中
- 2-3年内将在"AI排程引擎"赛道出现头部平台

**匹配策略**：差异化深耕 — 利用云筑网独占的"成本-工期-工序-劳动力"四维数据，先在中建体系内做到极致，再向外复制。不与广联达在"通用进度计划工具"层面正面竞争。

**行业预判结论**：🟢 6 模块全部通过，进入五步法项目分析。

## 三、五步法逐层分析

### Step 1 需求

**目标用户**：中建体系项目经理/总工程师 → 中国大型建筑企业 → 金融机构/业主（非"所有人"）

**场景与痛点**：

| 场景 | 痛点 | 刚性 |
|:---|:---|:---:|
| 投标阶段进度方案编制 | 手动排程耗时长（2-3天做一份计划），方案比选靠个人经验，不同方案优劣无法量化对比 | 🔴刚性 |
| 施工阶段动态进度优化 | 进度滞后时不知最优调整策略（加人？加班？改工序？），靠"拍脑袋"决策 | 🔴刚性 |
| 多项目资源调配 | 设备/人员跨项目闲置或短缺，缺乏全局最优调度，资源利用率低 | 🟡较强 |
| 劳务-进度协同 | 进度计划和可用劳动力脱节，不知道某个时间点能否招到足够工人 | 🟡较强 |
| 进度风险预测 | 无法提前预判哪些工序有延期风险，等问题暴露已来不及调整 | 🔴刚性 |
| AI施工方案自动生成 | 施工组织设计编写耗时数周，大量重复劳动，标准化程度低 | 🟡较强 |

**替代方案**：
- Primavera P6 / MS Project（手动排程工具，无AI优化能力）
- 广联达斑马进度计划（AI辅助生成，但以计划编制为主，缺乏动态优化）
- 项目经理经验判断（覆盖率低、主观性强、不可复制）
- Excel（中小企业仍大量使用）

**需求评估三角形**：
- 刚性：🔴 雪中送炭 — 建筑业利润率不足3%，工期延误直接吃掉利润；投标阶段排程速度直接决定中标率
- 频次：🔴 高频 — 每个项目投标+每月进度更新+每次变更调整都需要排程
- 普遍性：🔴 广泛 — 所有施工企业都有排程需求，从央企到民企

**关键假设**：
- H1（P0）：中建体系内项目经理认为手动排程是显著痛点，愿意使用AI排程工具替代
- H2（P1）：AI排程的工期预测准确度能显著优于项目经理经验判断（差距≥15%）

### Step 2 解决方案

**差异化定位**：

> 广联达斑马进度是"AI辅助画图工具"，ALICE/nPlan是"纯排程优化引擎"，我们是**"融合成本-工期-工序-劳动力四维约束的AI施工方案生成与动态优化平台"** — 核心差异在于：我们有**10万亿真实交易数据训练的"工序成本-工期"关联模型**和**1400万工人劳动力约束数据**，能回答"某个工序在当前市场条件下需要多少天、花多少钱、有多少可用工人"，而竞品只能基于通用定额做排程。

**核心卖点**：一句话 — **"别人告诉你工序要排几天，我们告诉你在这个工地、这个季节、用这些工人，实际需要几天。"**

**产品内核（做了什么、不做什么）**：

| 做 ✅ | 不做 ❌ |
|:---|:---|
| 基于真实交易数据的工序工期预测 | 通用进度计划画图工具（不与广联达斑马正面竞争） |
| 四维约束（成本+工期+工序+劳动力）自动排程 | 完全替代项目经理决策（AI推荐+人工确认） |
| 动态进度预警与最优调整方案推荐 | 工地IoT硬件（依托已有智慧工地） |
| 施工组织设计AI辅助生成 | 纯设计BIM建模（专注施工阶段） |
| 多项目资源跨项目调配优化 | 财务/合同管理（专注进度排程） |

**最小可用版本（MVP）**：
1. 选取中建1个工程局的3个在建项目，清洗其进度数据和成本数据
2. 用云筑网10万亿交易数据训练"工序-工期-成本"关联预测模型
3. 输出MVP：上传项目WBS → AI预测每道工序工期分布（P10/P50/P90）→ 生成推荐排程方案 → 与项目实际进度对比
4. 在项目月度进度更新中使用，验证AI排程准确度

**SharP定位**：
- 对项目经理：**"30分钟出3版可比的排程方案，每版告诉你工期多少天、多少钱、需要多少工人"**
- 对企业高管：**"知道每个项目真实的工期风险在哪里，提前2周预警"**

**关键假设**：
- H3（P0）：10万亿交易数据能有效提取"工序-工期-成本"关联关系，预测准确度优于行业定额
- H4（P0）：1400万工人数据能有效转化为可用劳动力约束（工种×地域×时间窗口）
- H5（P1）：大模型能从施工组织设计历史文档中学习排程逻辑，辅助生成方案

### Step 4 增长

**获客渠道清单**（优先级排序）：

- H11（P1）："成本-工期-工序"关联数据具有持续积累的网络效应（模型准度随数据量提升而显著提升）

## 七、备选路径

**Plan A（首选）**：AI施工排程引擎SaaS（四维约束：成本+工期+工序+劳动力）
- 路径：中建体系内1个局3项目MVP → 8个局推广 → 外部央企复制 → 金融机构API
- 目标：第3年收入2300万，第5年收入6000万+

**Plan B（备选）**：AI施工方案自动生成（不做排程优化，只做方案文本/图表生成）
- 路径：基于中建历史施工组织设计文档，训练大模型自动生成施工方案
- 优势：更轻资产，不需要运筹优化团队，大模型技术成熟度更高
- 劣势：差异化壁垒较薄（大模型方案生成竞品容易追赶），商业价值低于排程优化
- 目标：第3年收入1000万

**Plan C（备选）**：施工进度数据平台（不做AI，只做数据标准化+可视化）
- 路径：将4100+智慧工地数据标准化，输出统一进度数据API给第三方AI工具
- 优势：最快启动，0算法投入，纯粹数据变现
- 劣势：天花板低（数据服务费），不掌握AI核心价值
- 目标：第3年收入800万

**Plan D（退出条件）**：
- 验证期内（9个月）中建体系内≥3个工程局拒绝试点 → 内部场景不通
- 交易数据无法有效提取"工序-工期"关联 → 核心数据假设不成立
- 外部竞品（广联达斑马）在6个月内发布类似的"真实数据驱动AI排程" → 先发窗口关闭
- 法律合规审查结论为数据不可对外输出 → 仅限内部使用，市场天花板压缩至<5亿

                  │                        │                        │
