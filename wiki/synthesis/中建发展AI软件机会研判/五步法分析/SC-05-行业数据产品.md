## 二、行业预判（六模块）

### M1 拆解行业

**产业链图**

```
数据源层              加工层                交易层               终端用户
交易所数据    ──→  上海钢联(900+品类) ──→ 数据终端订阅   ──→  券商/期货
工厂/贸易商   ──→  生意社(BPI指数)    ──→ API接口服务    ──→  建筑企业
云筑网交易数据 ─→  水泥网/钢之家      ──→ 数据交易所挂牌  ──→  政府监测
```

**利润分配**

| 环节 | 毛利率 | 说明 |
|:---|:---:|:---|
| 数据采集与脱敏 | 30-40% | 合规成本刚性 |
| 指数编制与模型 | 70-80% | 核心算法能力 |
| 产品化与分发 | 50-60% | 终端/API/交易所挂牌 |
| 客户培育与销售 | 20-30% | 数据产品付费周期长 |

**关键控制节点**：**用户心智型** — Mysteel已建立行业品牌（铁矿石指数被全球四大矿山采用，30%全球贸易以其为结算依据），品牌壁垒极强。

**可优化环节**：建筑行业景气指数、供应商信用指数完全空白。现有数据产品以"大宗商品价格"为核心，缺少建筑行业特色的信用+景气维度。

### M2 洞察变化

| 维度 | 变化 | 量级 | 证据 |
|:---|:---|:---:|:---|
| **政策法规** | 17部门"数据要素×"三年行动计划，数据交易规模倍增 | 🔴大 | 2026年底300+应用场景 |
| **政策法规** | 财政部数据资产入表规定2024年实施 | 🟡中 | 打通财务路径 |
| **供给侧** | 全国39家数据交易所，38925个数据产品 | 🟡中 | 基础设施完善 |
| **供给侧** | 陕建首单建筑数据ABS（2025年7月） | 🟡中 | 数据证券化路径已通 |
| **需求侧** | 建筑业GDP占中国GDP约7%，但缺统一景气指数 | 🟡中 | 市场空白 |

**判断**：**中等变化** — 政策窗口打开，基础设施就绪，但数据产品需要较长的客户培育期，且Mysteel品牌壁垒极强。

### M3 预判稳态B

**稳态B推演**：

> （数据要素市场化政策推动）→（数据交易所蓬勃发展）→（建筑行业数据产品从无到有）→ **形成"价格指数（Mysteel主导）+ 信用指数+景气指数（新进入者机会）"的分层格局。**

中建发展在稳态B中的位置：**建筑行业信用指数+景气指数的定义者** — 价格指数市场Mysteel已占据，但供应商信用指数和行业景气指数完全空白。

### M4 Timing

**周期定位**：**早期探索期**

- 数据要素市场刚起步（2024年数据资产入表元年）
- 建筑行业数据产品几乎空白（仅Mysteel挂牌少数产品）
- 客户对数据产品的付费习惯尚未建立

**窗口期判断**：窗口**已开但较宽**，还有 **3-5 年**。数据产品不急于抢时间，但需要持续布局。

**太早风险**：**中高** — 客户付费习惯未建立，培育期长
**太晚风险**：低 — 市场尚处早期

### M5 天花板大小

| 方法 | 估算 | 说明 |
|:---|:---|:---|
| **直接数据** | 数据要素市场1662亿(2024)，年增20%+，2030年7000亿+ | 全行业 |
| **类比法** | 上海钢联8亿/年（大宗商品）→ 建筑行业至少2-3亿 | 数据产品 |

**结论**：建筑行业数据产品可触达市场 **5-15亿元**（长期），但需要较长培育期。

### M6 集中度

**现状**：**寡头（Mysteel主导价格数据）**
- Mysteel：30万+付费用户，IOSCO认证，全球影响力
- 其他：生意社/水泥网/钢之家细分领域跟随

**趋势**：**A型（分散→分散的可能性大）** — 数据产品品类多，不同品类可能形成不同头部。

**匹配策略**：差异化深耕 — 避开Mysteel的价格指数优势，做信用指数+景气指数等空白品类。

**行业预判结论**：🟡 4 模块通过，M4偏早（客户培育期长），M6偏集中（Mysteel主导价格品类）。

## 三、五步法逐层分析

### Step 1 需求

**目标用户**：券商/期货公司（研究定价）、建筑企业（市场对标）、政府（行业监测）、数据交易所

**场景与痛点**：

| 场景 | 痛点 | 刚性 |
|:---|:---|:---:|
| 券商行业研究 | 建筑业占GDP 7%但缺统一景气指数 | 🟡中等 |
| 建筑企业市场对标 | 供应商信用缺乏行业统一评估标准 | 🟡中等 |
| 政府价格监测 | 建材价格透明度不足 | 🟡中等 |
| 数据交易所 | 建筑类数据产品几乎空白 | 🟡中等 |

**需求评估三角形**：
- 刚性：🟡 中等 — "有了更好"而非"没有不行"
- 频次：🟡 中等 — 指数类产品每日更新，但订阅决策低频
- 普遍性：🟡 中等 — 需求存在但付费意愿待验证

**关键假设**：
- H1（P0）：券商/期货公司愿意为建筑行业景气指数/信用指数付费
- H2（P1）：数据脱敏后的交易数据仍然有足够的分析价值

### Step 2 解决方案

**差异化定位**：

> Mysteel卖"大宗商品价格数据"，我们卖**"建筑行业信用+景气数据产品"** — 不在价格品类上正面竞争，而是做Mysteel不做的品类：供应商信用评分、行业景气指数、履约风险指数。

**核心卖点**：**"Mysteel告诉你建材多少钱，我们告诉你建筑行业健不健康、供应商靠不靠谱。"**

**功能取舍**：

| 做 ✅ | 不做 ❌ |
|:---|:---|
| 供应商信用指数（基于10万亿交易数据） | 大宗商品价格指数（与Mysteel正面竞争） |
| 建筑行业景气指数 | 国际指数认证（IOSCO等） |
| 履约风险指数 | 衍生品/期货定价 |
| 数据交易所挂牌+API | C端个人数据产品 |

**关键假设**：
- H3（P0）：数据脱敏后不可反推原始交易（法律合规前提）
- H4（P1）："建筑行业景气指数"有真实市场需求（非自造需求）

### Step 3 商业模式

**单元模型选型**：**单客户（数据订阅）**

**收入测算**（第3年）：

| 收入来源 | 模式 | 规模 | 年收入 |
|:---|:---|:---|:---|
| 券商/期货终端订阅 | 年费10-30万 | 20家 | 400万 |
| 数据API调用 | 按次/包月 | 50家中小客户 | 200万 |
| 政府/协会定制 | 项目制 | 5个×50万 | 250万 |
| 数据交易所挂牌分成 | 交易额分成 | | 100万 |
| **第3年合计** | | | **950万** |

**成本结构**（第3年）：

| 成本项 | 金额 | 说明 |
|:---|:---|:---|
| 技术+数据团队 | 500万 | 数据脱敏+指数编制+产品化 |
| 合规与法务 | 200万 | 数据确权+脱敏认证+交易所挂牌 |
| 销售与获客 | 200万 | 券商/政府渠道 |
| 云服务 | 50万 | |
| **总成本** | **950万** | |
| **毛利** | **0（第3年盈亏平衡）** | 数据产品前期投入大 |

**关键判断**：数据产品是**长期资产**，前期投入大（合规+产品化+客户培育），第3年才盈亏平衡，第5年才能规模化盈利。与SC-01/SC-03相比，投入产出周期更长。

### Step 4 增长

**获客渠道**：

| 优先级 | 渠道 | CAC | 说明 |
|:---|:---|:---:|:---|
| 1 | 数据交易所挂牌 | 20万 | 交易所帮推广 |
| 2 | 券商研究所合作 | 10万 | 联合发布研报 |
| 3 | 政府价格监测合作 | 30万 | 发改委价格监测中心 |
| 4 | 行业协会 | 15万 | 中国建筑业协会 |

**增长引擎**：**付费式** — 数据产品需要主动营销和客户培育。

### Step 5 壁垒

| 壁垒类型 | 具体内容 | 强度 |
|:---|:---|:---:|
| **数据资产** | 10万亿交易数据是底层资产 | 🟡中（需脱敏，脱敏后价值可能下降） |
| **规模效应** | 数据越多指数越准 | 🟡中 |
| **无形资产** | 央企身份+数据交易所合作 | 🟡弱 |

**关键风险**：数据脱敏后的价值衰减 — 如果脱敏到不可反推原始交易的程度，数据的分析价值可能大幅降低。这是核心假设H2。

## 七、备选路径

**Plan A（首选）**：建筑行业数据超市（信用指数+景气指数+价格指数）
- 路径：先做供应商信用指数 → 交易所挂牌 → 扩展品类
- 目标：第5年5000万+

**Plan B（备选）**：数据资产入表+证券化（不做产品，做资产）
- 路径：将10万亿交易数据确认为数据资产 → 入表 → ABS融资
- 优势：不需要客户培育期，直接变现
- 目标：数据资产评估5-10亿，撬动融资2-3亿

**Plan C（退出条件）**：
- 数据脱敏后价值大幅衰减 → 放弃独立产品，数据仅供SC-01/SC-03内部使用
- 券商/政府付费意愿<20% → 市场不成熟，延迟2年再评估

## 八、建议下一步行动

**第一件事（本周）**：委托第三方安全审计机构对云筑网交易数据做一次脱敏方案评估

- **验证目标**：脱敏后数据是否仍可编制有意义的信用指数/景气指数
- **实验设计**：取1000条交易记录，按3种脱敏方案处理，对比分析价值衰减程度
- **成本预算**：2周 + 第三方审计费5-10万
- **成功标准**：至少1种脱敏方案下，指数编制偏差≤10%

## 九、与SC-01/SC-03的关系

SC-05 是 SC-01（风控）和 SC-03（金融）的**数据资产增值层**：

```
SC-01/SC-03（业务层）产生交易数据
        ↓
SC-05（资产层）将数据脱敏后产品化
        ↓
数据交易所挂牌 → 数据资产入表 → ABS融资
```

**建议**：SC-05 不应独立推进，而应作为 SC-01/SC-03 的副产品。当 SC-01/SC-03 运营到一定规模后，数据自然积累，再启动 SC-05 的产品化。当前阶段应聚焦**数据合规方案设计**和**脱敏技术验证**，不做产品投入。
