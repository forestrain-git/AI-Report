## 二、行业预判（六模块）

### M1 拆解行业

**产业链图**

```
资金端                平台端                  资产端                  终端用户
银行/保理公司  ──→  云筑网(中建电商)  ──→  供应商应收账款    ──→  中小建筑供应商
微众银行       ──→  中建资本         ──→  订单融资需求      ──→  核心建筑企业
联易融/中企云链 ─→  第三方金融科技    ──→  存货融资需求      ──→  金融机构
```

**利润分配**（100元供应链金融收入拆解）

| 环节 | 毛利率 | 说明 |
|:---|:---:|:---|
| 资金成本（银行放款） | 3-5% | 银行资金成本约3-4%，利差是核心收入 |
| 风控与合规 | 60-70% | AI模型边际成本极低，人工审核为主要成本 |
| 平台运营 | 30-40% | 系统维护+客户服务，随规模摊薄 |
| 获客与渠道 | 15-25% | 云筑网自有流量，获客成本趋零 |

**关键控制节点**：**数据资产型 + 渠道控制型** — 云筑网同时控制数据（10万亿交易记录）和渠道（110万供应商入口），双重控制。

**可优化环节**：传统供应链金融依赖核心企业确权，审批流程3-7天。AI驱动的"数据信用"模式可将审批压缩至小时级，同时覆盖传统模式不愿碰的中小供应商。

### M2 洞察变化

| 维度 | 变化 | 量级 | 证据 |
|:---|:---|:---:|:---|
| **政策法规** | 77号文推动"数据信用"替代"主体信用"，鼓励"脱核"模式 | 🔴大 | 六部门2025年4月发布，6月15日施行 |
| **政策法规** | 应收账款电子凭证付款期限≤6个月 | 🔴大 | 77号文硬约束，规范市场 |
| **需求侧** | 中小建筑供应商融资难融资贵，回款周期长 | 🔴大 | 建筑行业应收账款余额约8-10万亿（来源：国家统计局2023年建筑业统计数据）。原报告引用的107-127万亿数据经核实逻辑不成立（超过建筑业总产值31.6万亿），可能混淆了"全社会固定资产投资"或"累计发生额"等更大口径 |
| **新技术** | AI风控模型44个关键节点全自动稽查 | 🟡中 | 中建自有平台已验证 |
| **供给侧** | 云筑网信融宝已实现产品闭环 | 🟡中 | 13家银行直连，累计撮合700亿+ |
| **供给侧** | 竞品加速布局：电建AI智能审单、陕建首单数据ABS | 🟡中 | 同行验证赛道可行 |

**判断**：**系统性变化** — 政策（77号文"脱核"）+ 需求（8-10万亿应收账款待盘活）+ 技术（AI全自动风控）三重共振。这足以支撑百亿级平台。

### M3 预判稳态B

**原子级需求拆解**

| 用户 | 场景 | 解决什么问题 | 愿付多少钱 |
|:---|:---|:---|:---|
| 中小建筑供应商 | 应收账款融资 | 回款周期6-12个月，急需流动资金 | 年化利率6-12%（低于民间借贷） |
| 核心建筑企业 | 优化供应链资金效率 | 延长账期导致供应商流失 | 0（由供应商承担融资成本） |
| 银行/保理公司 | 获取优质资产 | 缺乏建筑行业交易数据做风控 | 平台分润0.5-1% |

**稳态B推演**：

> （77号文推动"脱核"）→（使得基于交易数据的自动化审批成为合规路径）→（AI风控模型降低坏账率）→（银行更愿意接入数据驱动的平台）→ **供应链金融从"核心企业信用背书"转向"数据信用驱动"，平台方凭借数据资产成为金融机构的基础设施。**

**中建发展在稳态B中的位置**：数据+渠道的双垄断者 — 10万亿交易数据做风控，110万供应商做入口，13家银行做通道。从"平台服务费"升级为"金融科技基础设施"。

### M4 Timing

**周期定位**：**早期探索 → 爆发增长的临界点**

- 77号文2025年6月施行，行业刚进入政策落地期
- 云筑网已有信融宝产品验证，但尚未全面升级为AI驱动模式
- 竞品（电建、陕建）在2024-2025年密集发布AI+供应链金融产品

**窗口期判断**：窗口**刚刚完全打开**，还有 **2-3 年**。

- 77号文施行后，银行合规需求在2026-2027年集中爆发
- 云筑网有先发优势（13家银行直连、700亿撮合额），但需加速AI升级
- "脱核"模式刚获政策许可，谁先跑通数据信用模型谁占先机

**太早风险**：**极低** — 信融宝已运营多年，不是从零开始
**太晚风险**：**中高** — 电建保理2025年已发布AI智能审单白皮书，陕建已发行首单建筑数据ABS

### M5 天花板大小

**四方法交叉验证**

| 方法 | 估算 | 说明 |
|:---|:---|:---|
| **直接数据** | 供应链金融整体41.8-45.8万亿(2024)，年增13.5-18.6% | 灼识咨询/清华五道口 |
| **Top-down** | 建筑行业应收账款余额8-10万亿 × 渗透率5% = 4-5千亿可服务规模 | 平台抽佣0.5-1% → 20-50亿收入空间 |
| **Bottom-up** | 云筑网110万供应商 × 假设10%有融资需求 × 年均50万 = 550亿 | 仅云筑网自身供应商池 |
| **类比法** | 联易融2023年营收约12亿港元 → 中建发展依托10万亿数据至少同等体量 | 建筑行业规模更大 |

**结论**：供应链金融AI可触达市场 **千亿级**（平台收入口径），支撑百亿级平台。云筑网仅吃中建体系内就能做到十亿级。

### M6 集中度

**现状**：**有头部玩家但建筑垂直领域未形成垄断**

- 跨行业头部：联易融（港股上市）、中企云链（央企系）
- 建筑央企自建：中建（信融宝/900亿+）、电建保理、陕建物流、浙建（2500亿）
- 银行系：微众银行（已与云筑网合作授信35亿）

**趋势**：**C型（分散→集中）★ 最佳时机**

- 数据资产+资金通道构成双重壁垒，先行者优势明显
- 77号文将加速行业规范化，不合规的小平台将被淘汰
- 建筑行业供应链金融将形成2-3个头部平台

**匹配策略**：**烧钱抢份额不适用** — 应利用云筑网现有数据+客户+银行通道优势，在中建体系内快速做深，再向外央企复制。

**行业预判结论**：🟢 6 模块全部通过，且全部为强通过。

## 三、五步法逐层分析

### Step 1 需求

**目标用户**：中小建筑供应商（资金需求方）+ 银行/保理公司（资金供给方）+ 核心建筑企业（供应链管理者）

**场景与痛点**：

| 场景 | 痛点 | 刚性 |
|:---|:---|:---:|
| 供应商应收账款融资 | 回款周期6-12个月，中小供应商现金流断裂风险高，民间借贷利率15-24% | 🔴刚性 |
| 订单融资 | 中标后需要垫资采购材料，资金缺口大 | 🔴刚性 |
| 银行获取优质资产 | 银行想做供应链金融但缺乏建筑行业交易数据做风控 | 🔴刚性 |
| 核心企业优化账期 | 延长账期导致优质供应商流失，需要金融工具缓冲 | 🟡中等 |

**替代方案**：

| 替代方案 | 局限性 |
|:---|:---|
| 银行传统信贷 | 需抵押物/担保，中小供应商达不到授信门槛 |
| 民间借贷/P2P | 利率15-24%，合规风险高 |
| 其他央企平台（电建/陕建） | 仅服务本体系内供应商，覆盖面有限 |
| 第三方平台（联易融/中企云链） | 缺乏建筑行业交易数据，风控精度不足 |

**需求评估三角形**：
- 刚性：🔴 雪中送炭 — 中小供应商融资是生存问题，不是改善问题
- 频次：🔴 高频 — 每笔订单都可能产生融资需求
- 普遍性：🔴 极广泛 — 建筑行业应收账款余额约8-10万亿（国家统计局2023年数据）

**关键假设**：
- H1（P0）：云筑网的交易数据能显著降低银行对中小供应商的风控成本和坏账率
- H2（P1）：银行愿意接受"数据信用"审批模式（而非传统的"核心企业确权"模式）

### Step 2 解决方案

**差异化定位**：

> 联易融/中企云链是"跨行业供应链金融平台"，我们是**"建筑行业数据信用基础设施"** — 区别在于：云筑网拥有建筑行业最大的真实交易数据（10万亿+），银行通过我们做风控比自己做更准、更快、更便宜。

**核心卖点**：一句话 — **"银行缺的不是钱，是敢放贷的数据。我们提供数据，银行提供钱，供应商拿到融资。"**

**产品内核（做了什么、不做什么）**：

| 做 ✅ | 不做 ❌ |
|:---|:---|
| AI风控模型升级（从规则引擎→机器学习） | 自己放贷（不做金融牌照业务） |
| 数据信用评估输出给银行 | 跨行业扩展（专注建筑） |
| 多品类融资（应收账款/订单/存货） | 个人消费金融 |
| "脱核"模式——供应商凭自身交易数据融资 | 仅依赖核心企业确权的传统模式 |

**最小可用版本（MVP）**：
1. 在现有信融宝基础上，将风控模型从规则引擎升级为机器学习模型
2. 选择1家合作银行做"数据信用"模式试点
3. 对比新旧模型的审批效率和坏账率
4. 验证通过后逐步推广到其他12家银行

**关键假设**：
- H3（P0）：机器学习模型的坏账率显著低于现有规则引擎（≥30%改善）
- H4（P1）：至少1家银行愿意在传统确权模式之外，接受纯数据信用审批

### Step 3 商业模式

**单元模型选型**：**单客户（ToB 平台）** — 按撮合交易额抽佣 + 风控服务费

**收入测算**（第3年估算）：

| 收入来源 | 模式 | 规模 | 年收入 |
|:---|:---|:---|:---|
| 撮合分润 | 撮合额 × 0.3-0.5% | 第3年累计撮合2000亿（新增600亿/年） | 1800-3000万 |
| 风控服务费 | 银行为数据查询付费 | 15家银行 × 200万/年 | 3000万 |
| 供应商增值服务 | 信用报告/融资咨询 | 5万次 × 100元/次 | 500万 |
| 平台技术服务费 | 系统对接/定制开发 | 10个项目 × 50万 | 500万 |
| **第3年合计** | | | **5800-6800万** |

**成本结构**（第3年估算）：

| 成本项 | 金额 | 说明 |
|:---|:---|:---|
| 技术团队（算法+工程+产品） | 1200万 | 15-20人，含风控模型持续迭代 |
| 银行渠道维护 | 300万 | 客户经理+系统对接维护 |
| 合规与法务 | 200万 | 77号文合规、算法备案 |
| 云服务/算力 | 300万 | 模型训练+推理+区块链节点 |

**LTV/CAC**：

| 指标 | 数值 | 判断 |
|:---|:---|:---|
| 银行客户年均收入 | 300万（分润+服务费） | |

**关键假设**：
- H5（P1）：第3年新增撮合额600亿（基于现有700亿存量的年化增速）
- H6（P2）：银行愿意为风控数据查询支付200万/年

### Step 4 增长

**获客渠道清单**（优先级排序）：

| 优先级 | 渠道 | 预估CAC | 说明 |
|:---:|:---|:---:|:---|
| 1 | **现有信融宝客户升级** | 0 | 已有13家银行直连+10万供应商 |
| 2 | **中建体系内推广** | 0 | 8个工程局的供应商自动接入 |
| 3 | **微众银行深度合作** | 10万 | 已授信35亿，扩大合作规模 |
| 4 | **其他央企平台接入** | 50-100万 | 中铁/中交/中铁建的供应商池 |
| 5 | **数据交易所挂牌** | 20万 | 信用评分作为数据产品上架 |

**增长引擎**：**黏着式 + 网络效应** — 
- 银行接入后难以切换（数据+系统深度绑定）
- 供应商越多 → 交易数据越丰富 → 风控越准 → 银行更愿接入 → 吸引更多供应商

**增长三阶段**：

| 阶段 | 核心任务 | 关键指标 | 时间 |
|:---|:---|:---|:---|
| 商业验证 0-1 | 信融宝AI升级 + 1家银行"脱核"试点 | 坏账率对比、审批效率 | 0-6个月 |
| 增长早期 1-10 | 13家银行全面升级 + 中建体系外2家央企 | 撮合额增速、银行数 | 6-18个月 |
| 加速增长 10-100 | 多品类融资 + 数据产品化 + 行业复制 | GMV、毛利率 | 18-36个月 |

**关键假设**：
- H7（P0）：中建资本支持云筑网独立发展供应链金融科技能力（而非将其锁定为内部工具）
- H8（P1）：其他央企愿意通过中建的平台做供应链金融（竞争关系是障碍）

### Step 5 壁垒

**壁垒类型**：

| 壁垒类型 | 具体内容 | 强度 |
|:---|:---|:---:|
| **数据资产** 🔑 | 10万亿真实交易数据 — 银行/竞品无法获取 | 🟢强 |
| **网络效应** 🔑 | 双边网络：供应商越多→数据越好→银行越愿接入→吸引更多供应商 | 🟢强 |
| **转化成本** | 银行系统直连+数据接口深度绑定，切换成本极高 | 🟢强 |
| **规模效应** | 风控模型边际成本趋零，规模越大成本越低 | 🟡中 |
| **无形资产** | 央企身份+中建品牌=金融机构天然信任 | 🟡中 |

**可复制性评估**：
- 联易融/中企云链复制：**极难** — 他们没有建筑行业10万亿交易数据，通用平台的风控精度不够
- 其他建筑央企复制：**2-3年** — 电建/陕建有自有数据但规模远小于云筑网
- 银行自建：**极难** — 银行缺乏供应商侧的交易数据，只有信贷数据

**关键假设**：
- H9（P0）：数据资产的确权和合规使用不受77号文后续细则的限制

## 十、与SC-01供应商智能风控的协同关系

SC-03（供应链金融AI）和 SC-01（供应商智能风控）是**同一数据资产的两层变现**：

```
数据资产层（共享）
  └── 10万亿交易履约数据 + 110万供应商画像
        │
        ├──→ SC-01 风控输出层（基础设施）
        │     准入审核 / 履约监控 / 围串标识别
        │     → 收入：SaaS订阅 + API调用
        │
        └──→ SC-03 金融变现层（核心引擎）
              应收账款融资 / 订单融资 / 存货融资
              → 收入：撮合分润 + 风控服务费
```

**组合效应**：
- SC-01 建立供应商信用评分体系 → SC-03 用评分做贷款审批输入
- SC-01 持续监控供应商履约 → SC-03 用监控数据做贷后风控
- SC-01 围串标识别 → SC-03 排除高风险供应商的融资申请

**建议**：SC-01 和 SC-03 共享技术底座（数据中台+AI模型），分两层变现。SC-03 的变现能力远强于 SC-01（金融分润 vs SaaS订阅），应优先投入 SC-03 的"脱核"模式验证。

## 十一、验证三步追问

### 5.1 谁的利益被消解

- **传统保理公司**：银行直接通过平台获取供应商资产，绕过保理公司中介
- **核心企业财务公司**："脱核"模式削弱核心企业的信用背书价值，财务公司的资金归集功能被替代
- **联易融/中企云链**：建筑行业数据信用模式若跑通，第三方平台在建筑垂直领域的竞争力下降

### 入口竞争风险分析（复审补充·2026-06-16）

**核心风险：微众银行从合作方转为竞争方**

微众银行已与云筑网合作授信35亿，但微众银行自身也在建设供应链金融科技平台。其微业贷产品已覆盖建筑行业中小供应商，具备从"资金方"延伸为"科技平台"的能力。

| 维度 | 中建发展（供应链金融AI） | 微众银行（供应链金融科技） |
|:---|:---|:---|
| 数据来源 | 云筑网10万亿交易数据 | 自有贷款数据+合作平台数据 |
| 客户关系 | 供应商入驻云筑网 | 供应商已有贷款关系 |
| 资金能力 | 需对接银行（13家直连） | 自有资金+银行间市场 |
| 技术能力 | AI风控模型（待建设） | 已有成熟的信贷风控模型 |
| 竞争策略 | 数据平台方，不放贷 | 从放贷延伸到数据服务 |

**此外，中建资本的协调风险**：云筑网与中建资本存在利益关系。AI独立对外输出供应链金融科技服务可能触动中建资本的利益格局。建议在推进前明确组织架构安排——是独立运营、与中建资本合作、还是作为中建资本的技术供应商。

**应对建议**：
1. 明确定位为"数据平台方"而非"金融服务方"——不与银行/微众抢客户，而是为银行提供风控数据服务
2. 与微众银行建立"竞合"关系——在数据服务层合作，在金融服务层各做各的
3. 优先推进中建资本协调——这是组织架构前置条件，技术不是瓶颈
