## 二、行业预判（六模块）

### M1 拆解行业

**产业链图**

```
数据源层                平台层                  应用层                终端用户
工商/司法/税务  ──→  天眼查/企查查/启信宝  ──→  供应商准入SaaS  ──→  建筑企业采购部
                     云筑网(中建电商)       ──→  履约风控SaaS    ──→  金融机构
                     广联达/筑集采          ──→  围串标识别      ──→  纪检监察
```

**利润分配**（100元收入拆解）

| 环节 | 毛利率 | 说明 |
|:---|:---:|:---|
| 数据采集与清洗 | 15-20% | 工商/司法数据采购成本刚性 |
| 风控模型研发 | 60-70% | 算法团队是核心成本，边际成本极低 |
| 产品化与交付 | 40-50% | SaaS模式边际成本低，定制化拉低毛利 |
| 销售与获客 | 20-30% | ToB销售团队重，CAC高 |

**关键控制节点**：**数据资产型** — 云筑网拥有 10 万亿级真实交易履约数据，这是通用企业信息平台（天眼查/企查查/启信宝）无法获取的独占资源。

**可优化环节**：建筑企业采购风控长期依赖人工审核（Excel + 经验判断），自动化替代空间巨大。启信慧眼已有"采购风控版"产品，但缺乏建筑行业交易履约维度的数据。

### M2 洞察变化

| 维度 | 变化 | 量级 | 证据 |
|:---|:---|:---:|:---|
| **政策法规** | "77号文"推动供应链金融从"主体信用"→"数据信用" | 🔴大 | 六部门2025年发布，6月15日施行 |
| **政策法规** | 八部门AI+招投标强制时间表 | 🔴大 | 多部门联合发文推动AI+招投标（具体文号待查证），2027年全国推广 |
| **新技术** | 大模型+知识图谱自动构建供应商画像 | 🟡中 | 工商银行风控大模型准确率97.8% |
| **新技术** | 隐私计算解决跨机构数据合规共享 | 🟡中 | 联邦学习渗透率达65% |
| **需求侧** | 建筑央企采购数字化率仅10-15% | 🔴大 | 天眼查/启信宝向供应链管理扩展验证需求存在 |
| **供给侧** | 云筑网已有110万+供应商 + 信融宝产品基础 | 🟡中 | 13家银行直连，累计撮合700亿+ |

**判断**：这是一个**系统性变化** — 政策（77号文 + AI+招投标）+ 技术（大模型 + 隐私计算）+ 需求（建筑采购数字化率极低）三重共振。变化量级足以支撑百亿级公司。

### M3 预判稳态B

**原子级需求拆解**

| 用户 | 场景 | 解决什么问题 | 愿付多少钱 |
|:---|:---|:---|:---|
| 建筑央企采购部 | 供应商准入审批 | 人工审核效率低、遗漏风险 | 3-10万/年 |
| 建筑央企采购部 | 履约过程监控 | 供应商经营异常无法及时发现 | 含在订阅中 |
| 金融机构（银行） | 供应链金融贷前风控 | 中小供应商信用评估难 | 按查询次数或定制100万+/年 |
| 纪检监察部门 | 围串标合规审查 | 人工排查效率低、覆盖面窄 | 50-200万/年（政府采购） |

**稳态B推演**：

> （77号文推动"数据信用"）→（使得基于真实交易数据的风控模型成为合规刚需）→（叠加AI+招投标强制政策）→ **建筑行业供应商风控从"人工经验驱动"转向"AI+数据驱动"，头部平台凭借独占数据资产形成寡头格局。**

**中建发展在稳态B中的位置**：数据资产层的独占者 — 拥有建筑行业最大的真实交易履约数据（10万亿+），且数据嵌入实际采购流程形成闭环，竞争对手无法复制。

### M4 Timing

**周期定位**：**早期探索 → 爆发增长的过渡期**

- 通用企业信息平台（天眼查/企查查/启信宝）已完成市场教育
- 建筑行业垂直的供应商风控SaaS尚处早期，启信慧眼"采购风控版"刚推出
- 云筑网已有数据基础和产品原型（信融宝），但尚未独立拆分为风控SaaS产品

**窗口期判断**：窗口已开，还有 **2-3 年**。原因：
- 77号文2025年6月施行，金融机构合规需求将在2026-2027年集中爆发
- 八部门AI+招投标要求2027年全国推广，倒逼建筑企业采购AI风控工具
- 竞品（天眼查/启信宝）正在向供应链管理扩展，但缺乏建筑行业交易数据

**太早风险**：低 — 云筑网数据和产品基础已就绪，不存在市场教育问题
**太晚风险**：中 — 启信慧眼已有"采购风控版"，若不尽快推出建筑行业专属产品，通用平台可能蚕食市场

### M5 天花板大小

**四方法交叉验证**

| 方法 | 估算 | 说明 |
|:---|:---|:---|
| **直接数据** | 智能风控整体市场 890亿(2025)→2600亿(2030) | 年复合24.6%，含银行/保险等全行业 |
| **Top-down** | 供应链金融风控 3.2万亿业务规模 × 风控服务费率1-3% = 320-960亿 | 建筑行业占比约20% → 64-192亿 |
| **Bottom-up** | 110万供应商 × 假设5%付费 × 年均2万 = 11亿 | 仅云筑网自身供应商，保守估算 |
| **类比法** | 上海钢联数据服务8亿/年（大宗商品）→ 建筑供应商风控至少同等体量 | 差异化品类 |

**结论**：建筑行业供应商智能风控可触达市场 **50-200亿元**，支撑十亿级体量公司。若叠加供应链金融场景（风控作为金融业务的基础设施），天花板更高。

### M6 集中度

**现状**：**有头部玩家但未形成垄断**
- 通用层：天眼查/企查查/启信宝三足鼎立
- 建筑垂直层：云筑网在中建体系内占主导，但行业覆盖面有限
- 无全国性建筑行业供应商风控SaaS寡头

**趋势**：**C型（分散→集中）★ 最佳时机**
- 数据资产具有网络效应和规模效应 — 数据越多，模型越准，客户越多
- 政策推动（77号文 + AI+招投标）将加速行业整合
- 2-3年内将出现建筑行业供应商风控的头部平台

**匹配策略**：差异化深耕 — 利用云筑网独占的交易履约数据，在建筑行业做深做透，而非与天眼查/启信宝在通用市场正面竞争。

**行业预判结论**：🟢 6 模块全部通过，进入五步法项目分析。

## 三、五步法逐层分析

### Step 1 需求

**目标用户**：建筑央企及大型建筑企业的采购管理部门（非"所有人"）

**场景与痛点**：

| 场景 | 痛点 | 刚性 |
|:---|:---|:---:|
| 供应商准入审批 | 人工审核营业执照/资质证书/安全许可证，效率低、易遗漏，平均审核周期3-5天 | 🔴刚性 |
| 履约过程监控 | 供应商经营异常（诉讼/失信/股权变更）无法及时发现，发现时已造成损失 | 🔴刚性 |
| 围串标识别 | 人工排查140万次招标数据中的关联关系和异常报价，覆盖率极低 | 🔴刚性 |
| 供应链金融风控 | 中小供应商信用评估缺乏数据支撑，银行不敢放贷 | 🔴刚性 |

**替代方案**：天眼查/企查查企业版（通用工商司法数据，缺乏建筑行业交易履约维度）、人工经验判断（覆盖率低、主观性强）

**需求评估三角形**：
- 刚性：🔴 雪中送炭 — 政策合规刚需（77号文 + AI+招投标）
- 频次：🔴 高频 — 每次采购/招标都需要风控审查
- 普遍性：🔴 广泛 — 所有建筑央企和大型建筑企业都有需求

**关键假设**：
- H1（P0）：建筑央企采购部门愿意为"建筑行业专属"的供应商风控SaaS付费（而非直接用天眼查企业版）
- H2（P1）：云筑网的交易履约数据对外部客户（非中建体系内）有足够吸引力

### Step 2 解决方案

**差异化定位**：

> 天眼查/企查查/启信宝是"企业工商信息查询工具"，我们是"建筑行业供应商全生命周期风控平台" — 区别在于：我们有**10万亿真实交易履约数据**，能回答"这个供应商在中建体系内的实际表现如何"，而通用平台只能回答"这个供应商在工商/司法层面有没有问题"。

**核心卖点**：一句话 — **"工商数据告诉你是谁，交易数据告诉你靠不靠谱。"**

**产品内核（做了什么、不做什么）**：

| 做 ✅ | 不做 ❌ |
|:---|:---|
| 供应商准入AI审核（资质核验+信用评分） | 通用企业信息查询（与天眼查正面竞争） |
| 履约过程动态监控（异常预警） | 供应链管理全流程SaaS（专注风控） |
| 围串标AI识别（关联关系+报价异常） | 金融牌照业务（不做信贷，只做风控输出） |
| 交易履约数据API输出（供银行/金融机构调用） | C端个人征信（不做个人信用评估） |

**最小可用版本（MVP）**：
1. 基于云筑网110万供应商数据，训练履约预测模型
2. 整合外部工商/司法数据补充
3. 输出动态信用评级（A/B/C/D四档）
4. 嵌入中建体系内采购流程做内部验证

**关键假设**：
- H3（P0）：云筑网交易数据 + 外部工商数据融合后的风控模型，预测准确率显著优于纯工商数据模型
- H4（P1）：大模型+知识图谱技术能有效构建建筑行业供应商关联关系图谱

### Step 3 商业模式

**单元模型选型**：**单客户（ToB SaaS）** — 按企业年订阅 + 按查询次数混合计费

**收入测算**：

| 收入来源 | 单价 | 客户基数（第3年） | 年收入 |
|:---|:---|:---|:---|
| 建筑央企采购部（标准版） | 10万/年 × 20家 | 中建系+其他央企 | 200万 |
| 大型建筑企业（标准版） | 5万/年 × 100家 | 省级建工集团等 | 500万 |
| 中小供应商自助查询 | 200元/次 × 5万次/年 | 供应商自身信用管理 | 100万 |
| 金融机构API调用 | 100万/年 × 5家 | 银行/保理公司 | 500万 |
| 围串标专项（政府采购） | 50万/年 × 10个项目 | 公共资源交易中心 | 500万 |
| **第3年合计** | | | **1800万** |

**成本结构**（第3年估算）：

| 成本项 | 金额 | 说明 |
|:---|:---|:---|
| 技术团队（算法+工程） | 600万 | 8-10人，含大模型训练 |
| 外部数据采购 | 200万 | 工商/司法/税务API |
| 云服务/算力 | 150万 | 模型训练+推理 |
| 销售与获客 | 400万 | ToB销售团队3-5人 |
| **总成本** | **1350万** | |
| **毛利** | **450万** | **毛利率25%** |

**LTV/CAC**：

| 指标 | 数值 | 判断 |
|:---|:---|:---|
| 年均客单价 | 8万（加权平均） | |
| 月均收入 | 0.67万 | |
| 月流失率 | 3%（SaaS低流失） | ✅ 健康 |
| LTV | 0.67万/3% = 22万 | |
| CAC | 4万（ToB销售） | |
| **LTV/CAC** | **5.5** | ✅ 健康（>3） |
| 回收期 | 4万/0.67万 = 6个月 | ✅ 合理 |

**关键假设**：
- H5（P1）：第3年能获取100家大型建筑企业客户
- H6（P2）：金融机构愿意为API调用支付100万/年

### Step 4 增长

**获客渠道清单**（优先级排序）：

| 优先级 | 渠道 | 预估CAC | 说明 |
|:---:|:---|:---:|:---|
| 1 | **中建体系内复制** | 0（内部推广） | 8个工程局 + N个子公司，0商务风险 |
| 2 | **云筑网现有客户转化** | 1-2万 | 110万注册供应商中的建筑企业 |
| 3 | **行业协会/政府渠道** | 3-5万 | 中国建筑业协会、各地公共资源交易中心 |
| 4 | **金融机构联合推广** | 2-3万 | 与13家合作银行联合推荐给建筑企业客户 |
| 5 | **内容营销+行业会议** | 5-8万 | 建筑行业数字化峰会、白皮书 |

**增长引擎**：**黏着式** — 供应商风控是嵌入采购流程的基础设施，用了就离不开（DAU/MAU高、留存率高）

**增长阶段**：

| 阶段 | 核心任务 | 关键指标 | 时间 |
|:---|:---|:---|:---|
| 商业验证 0-1 | 中建体系内部验证 + 信融宝客户转化 | 内部NPS、模型准确率 | 0-6个月 |
| 增长早期 1-10 | 央企横向复制 + 金融机构API | 外部客户数、API调用量 | 6-18个月 |
| 加速增长 10-100 | 省级建工集团 + 政府采购 | CAC趋势、客户增速 | 18-36个月 |

**关键假设**：
- H7（P0）：中建体系内各局愿意使用云筑网的风控产品（而非自建或外采天眼查）
- H8（P1）：中建体系外的建筑央企（中铁/中交/中铁建等）愿意接入中建的风控平台

### Step 5 壁垒

**壁垒类型**：

| 壁垒类型 | 具体内容 | 强度 |
|:---|:---|:---:|
| **数据资产** 🔑 | 10万亿真实交易履约数据 — 通用平台无法获取 | 🟢强 |
| **网络效应** | 供应商越多 → 数据越丰富 → 模型越准 → 吸引更多客户 | 🟢强 |
| **规模效应** | 数据边际成本趋零，模型训练成本被客户数摊薄 | 🟡中 |
| **转化成本** | 嵌入采购流程后，切换成本高（数据迁移+流程重建） | 🟡中 |
| **无形资产** | 央企身份+中建品牌背书 | 🟡中 |

**可复制性评估**：
- 天眼查/启信宝复制：**极难** — 他们没有建筑行业交易履约数据，工商数据是公开的，但"中建体系内供应商实际表现如何"是独占数据
- 其他建筑央企复制：**2-3年** — 中铁/中交等有自有平台数据，但规模远小于云筑网（云筑网110万供应商 vs 其他平台通常10-30万）
- 新进入者复制：**几乎不可能** — 需要同时具备行业数据+客户基础+政策资质

**关键假设**：
- H9（P0）：云筑网的交易数据在法律上可以用于风控产品对外输出（数据确权与合规）

## 八、备选路径

**Plan A（首选）**：建筑行业供应商全生命周期风控SaaS
- 路径：中建体系内验证 → 央企横向复制 → 金融机构API → 政府采购
- 目标：第3年收入1800万，第5年收入8000万+

> **⚠️ 前提**：数据合规审查通过（H9），且外部客户付费意愿确认（H1）。如果H9不通过，则Plan A需要重新定义为"仅限中建体系内的内部工具"。

**Plan B（备选）**：仅限中建体系内的供应商风控工具
- 路径：合规不通过时的降级方案，仅供中建内部8个工程局使用
- 优势：无合规风险，零获客成本
- 局限：收入天花板降至300-500万/年，不再是独立业务线而是内部效率工具

**Plan C（备选）**：供应链金融风控数据服务（不做SaaS，只做数据输出）
- 路径：将交易履约数据封装为API，输出给银行/金融机构用于信贷风控
- 优势：更轻资产，无需ToB销售团队，直接对接金融机构
- 目标：第3年5家金融机构，API收入500万/年

**Plan D（退出条件）**：
- 验证期内（6个月）中建体系内≥3个工程局拒绝使用 → 内部需求不成立
- 法律合规审查结论为数据不可对外输出 → 仅限体系内使用，市场天花板大幅缩小
- 模型准确率无法显著优于纯工商数据方案 → 差异化不成立

## 九、建议下一步行动（最小验证）

**第一件事（本周）**：**做合规审查，而不是做技术原型。** 这是和SC-03/IS-B08最大的不同——这个方向的致命风险在合规层面，不在技术层面。

1. **合规审查**（1-2周）：调取云筑网供应商入驻协议，查是否有数据用于第三方风控的授权条款；同时请外部律师评估77号文第（四）条是否覆盖此场景
2. **客户访谈**（并行进行）：匿名访谈5-10家外部建筑央企采购负责人，测试付费意愿
3. **技术验证**（合规通过后启动）：在中建体系内选1个工程局做数据+工商A/B对比测试

**第一件事（本周）**：在中建体系内选择 1 个工程局的采购部门，用云筑网数据 + 天眼查数据做一次 A/B 对比测试

- **验证目标**：交易数据加持后的风控模型，准确率是否比纯工商数据高 15 个百分点以上
- **实验设计**：
  1. 选取该局近 1 年的 100 个供应商准入案例（含 20 个已知风险供应商）
  2. 分别用"纯工商数据"和"工商数据+云筑网交易数据"做风控评分
  3. 对比两组模型的准确率/召回率/误报率
- **成本预算**：2 周时间 + 1 名算法工程师 + 0 元外部采购（数据已有）
- **成功标准**：交易数据模型的 AUC ≥ 0.85，且比纯工商模型提升 ≥ 15%

## 九、与供应链金融AI（SC-03）的协同关系

供应商智能风控（SC-01）与供应链金融AI（SC-03）是**天然的上下游关系**：

```
SC-01 供应商风控（基础设施层）
  │
  ├── 供应商准入审核 → 信用评级输出
  ├── 履约过程监控 → 动态风险评估
  └── 围串标识别 → 合规背书
  │
  ▼
SC-03 供应链金融（变现层）
  │
  ├── 信用评级作为贷款审批输入
  ├── 动态风险评估作为贷后监控
  └── 合规背书降低银行风控成本
```

**建议**：SC-01 和 SC-03 应作为"组合拳"推进 — SC-01 建立数据壁垒和客户基础，SC-03 实现金融变现。两者共享同一套数据资产和技术底座，边际成本极低。
