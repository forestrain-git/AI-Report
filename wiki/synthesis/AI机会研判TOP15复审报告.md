### LW-04 劳务市场行情指数（81 → 79）

#### 核心论据清单
1. 云筑网拥有1400万工人实时工价数据，广联达仅6万条
2. 住建部工程造价改革试点（北京/浙江/湖北/广东/广西）
3. 建筑业年产值31万亿，人工成本占比30-40%，TAM 50-200亿
4. 70%毛利率数据产品模式，LTV/CAC=5.5
5. 定额人工单价180元/天 vs 市场实际价350-500元/天

#### 论据校验

| 论据 | 校验 | 详情 |
|------|------|------|
| 1400万工人数据 | ⚠️需补充 | 1400万是累计注册数还是月活？实名制打卡数据经清洗后，实际有效"工种×地区×时间"三维数据量可能远小于此。报告硬伤卡牌#5已提及此风险，但正文仍以1400万作为核心卖点，**存在内部矛盾** |
| 广联达仅6万条 | ❌存疑 | 数据量来源需核实。广联达造价软件覆盖全国，工价数据可能不止6万条。更重要的是，广联达可通过造价软件（成本部标配）直接bundle工价模块，**无需在数据量上追平** |
| 建筑业年产值31万亿 | ✅已验证 | 国家统计局2024年数据，建筑业总产值约31.2万亿 |
| 人工成本占比30-40% | ✅已验证 | 行业公开数据，住建部定额司有类似口径 |
| 定额180元 vs 市场350-500元 | ⚠️需补充 | 定额人工单价因地区、工种差异大。180元/天是全国均价还是特定地区？350-500元是最高价还是均价？需标注统计口径和来源 |
| Wind对标30亿/年 | ⚠️需补充 | Wind的商业模式（金融高频交易+机构订阅）与建筑工价指数（低频+政府定价参考）存在**本质差异**，类比合理性存疑 |

#### 关键风险
- **数据质量悖论**：正文强调1400万数据是核心壁垒，硬伤卡牌却承认"实名制打卡数据≠直接可用的工价指数"
- **广联达bundle竞争被低估**：造价软件是建筑央企成本部标配，可在软件内直接嵌入工价模块——"免费捆绑"的竞争威胁未被分析
- **PIPL合规是前置条件**：工人工资属个人敏感信息，用于商业指数产品需额外授权。这不是"可控P0"而是"必须通过的前置条件"
- **政府定额体系不会轻易退出**：涉及地方财政、招投标规则、审计依据等多方利益，退出周期可能远超3-5年

#### 修改建议
1. 将"1400万"细化为"经清洗后可用三维数据量"，明确数据清洗预期损耗率
2. 广联达6万条需标注来源，如无法核实则改为"远小于云筑网"的定性描述
3. **增加广联达bundle竞争的专门分析**（至少1段），评估其造价软件内嵌工价模块的可行性和时间窗口
4. PIPL合规从"可控P0"提升为"必须通过的前置条件"，增加法律合规审查时间表
5. Wind对标增加差异分析：使用频次、客户支付意愿、市场成熟度均有本质差异

### SC-03 供应链金融AI（80 → 78）

#### 核心论据清单
1. 云筑网10万亿交易数据 + 110万供应商
2. 77号文推动数据信用替代主体信用，鼓励脱核模式
3. 信融宝已运营多年，13家银行直连，累计撮合700亿+
4. 供应链金融整体41.8-45.8万亿(2024)，建筑行业AR 107-127万亿
5. 银行LTV/CAC=30，毛利率59-65%

#### 论据校验

| 论据 | 校验 | 详情 |
|------|------|------|
| 10万亿交易数据 | ⚠️需补充 | 累计还是年交易额？银行做风控需要单笔交易级别的明细数据，而非汇总数据 |
| 77号文"鼓励脱核" | ✅已验证 | 六部门2025年4月发布，但注意是"鼓励"而非"强制"，银行执行力度不确定 |
| 信融宝700亿+撮合 | ✅已验证 | 确有此数据，但700亿是累计撮合额，年化增速和坏账率需补充 |
| 建筑行业AR 107-127万亿 | ❌存疑 | 数据来源不明。需区分"应收账款余额"和"年发生额"，且估算范围过大（偏差20%） |
| 银行LTV/CAC=30 | ⚠️需补充 | 年均收入300万基于"15家银行×200万/年"，但银行是否愿意为风控数据单独付费200万/年需要商务验证 |

#### 关键风险
- **"数据信用"模式仅在POC阶段**：77号文是"鼓励"非"强制"，银行是否主动采用存在重大不确定性
- **中建资本协调是隐性硬伤**：AI独立对外输出可能触动中建资本利益格局，未在报告中充分展开
- **坏账率假设偏乐观**：报告假设ML模型坏账率≤1.5%，但建筑行业供应链金融通常2-3%
- **竞品分析不完整**：微众银行已合作授信35亿，但其自身也在做供应链金融科技，可能从合作方变为竞争方

#### 修改建议
1. 将"数据信用模式"从"已验证"调整为"假设待验证"，增加验证时间表
2. 增加中建资本协调的专门分析，明确AI独立对外输出的组织架构安排
3. 坏账率从1.5%调整为1.5-2.5%的区间估计，并做敏感性分析
4. 增加微众银行从合作方转为竞争方的风险分析
5. 107-127万亿AR数据需标注来源，如无法核实则删除

### IS-A01 海外部投标评审（80 → 79）

#### 核心论据清单
1. 技术版本已交付集团海外部，有真实业务场景验证
2. 国资委推动央企穿透式监管，追责情形从72种扩至98种
3. 中建海外营收1,416.98亿元（+22.20%）
4. 3人团队轻量启动，算力成本由中建数科承担
5. 国际工程EPC合同条款+FIDIC体系+多国建筑法规的行业know-how

#### 论据校验

| 论据 | 校验 | 详情 |
|------|------|------|
| 已交付集团海外部 | ✅已验证 | **5份报告中唯一有实际交付的**，需求验证最强 |
| 穿透式监管追责98种 | ⚠️需补充 | "国资委46号令"需标注具体文号。72种→98种的数据来源需核实 |
| 海外营收1,416.98亿 | ✅已验证 | 中建2024年年报数据 |
| 3人团队正向盈利 | ⚠️需补充 | 算力成本由中建数科承担是否写入长期协议？如无则成本结构可能突变 |
| EPC/FIDIC行业know-how | ✅已验证 | 确实是建筑行业海外投标核心知识，通用AI产品难以覆盖 |

#### 关键风险
- **天花板偏小**：中建体系内5000万-1.5亿，扩展至其他央企5-10亿。即使成功也只是内部产品线，非独立商业产品
- **集团发文依赖**：H7（集团发文推动）是P0假设，决策周期和政治复杂度可能被低估
- **多语言准确率假设偏乐观**：建筑行业专业术语（FIDIC条款、各国建筑法规）对大模型挑战远大于通用文本
- **GDPR合规风险**：涉及欧盟业务的海外机构存在重大合规风险，报告仅提及未展开

#### 修改建议
1. 明确算力成本承担安排是否写入长期协议，如无则增加成本敏感性分析
2. 增加GDPR合规专门分析段落
3. 多语言准确率从"准确理解"调整为"基本理解+人工复核"，明确人工复核比例和成本
4. 增加集团发文决策周期估计及各机构执行力度差异化分析
5. 天花板估算需明确是否包含外部央企市场及获客难度

#### 论据校验

| 论据 | 校验 | 详情 |

4. 用30%事故预防率重算，G品类评分应回调至75-78分区间

### FUT-D AI自动合约生成（80 → 75）

#### 核心论据清单
1. AI让法律判断成本趋零，每个项目获得顶级律师级别合同初稿
2. 演进路径：IS-A04（合同审查，46分）→ FUT-D（从"审"到"写"）
3. 全行业年损失640-860亿（直接人力80-300亿+合同质量损失560亿）
4. 穿越对标：Westlaw（20年）、TurboTax（30年覆盖60%）、CAD（15年达50%渗透率）
5. 中建体系百万份合同数据是独占壁垒

#### 论据校验

| 论据 | 校验 | 详情 |
|------|------|------|
| IS-A04作为垫脚石 | ❌存疑 | **IS-A04当前仅46分（末档），排名倒数**。核心风险：红海竞争+B型寡头格局+仅1-2年窗口期。如果IS-A04失败，FUT-D的知识库积累和信任基础就不存在 |
| 全行业年损失640-860亿 | ⚠️需补充 | 合同质量损失560亿推导链较长（涉案金额→归因比例→可避免比例），每步有衰减。保守估计可释放价值可能在200-400亿区间 |
| 通用LLM合同生成已成熟 | ⚠️需补充 | Harvey AI（$1.5B估值）服务英美法系大型律所，与中国建筑行业合同体系（大陆法系+住建部规范+FIDIC本土化）差异显著。**"通用LLM→建筑垂直"的gap未被论证** |
| 中建合同数据独占 | ⚠️需补充 | "百万份合同"需核实数量和可结构化程度。国资委推动数据共享可能削弱独占优势 |
| 触发确定性最高（14分） | ✅已验证 | 双扳机设计使触发条件可观测，IS-A04进度提供直接可测量指标 |

#### 关键风险
- **IS-A04垫脚石风险最严重**：IS-A04仅46分，如果失败，FUT-D整条演进路径失去基础
- **"触发确定性14分"与IS-A04的46分存在张力**：如果IS-A04"需重大调整"，触发指标的确定性是否应下调？
- **建筑行业法务保守程度可能高于预期**：穿越对标中CAD用了10年才被接受

#### 修改建议
1. **增加"IS-A04失败"备选路径**：FUT-D是否可独立建设建筑合同知识库？成本和时间线如何变化？
2. 下调解锁价值至保守区间：200-400亿/乐观640-860亿
3. 补充建筑行业合同特殊性技术论证：通用LLM在EPC/FIDIC/分包合同条款理解上的gap
4. 触发确定性从14分下调至12分（考虑IS-A04的46分判定）

### FUT-B Agent协同（73 → 68）

#### 核心论据清单
1. AI Agent代替人工完成B2B交期协商、价格谈判、履约确认
2. 梅特卡夫式网络效应：n个节点→n*(n-1)/2条潜在对话链路
3. 云筑网110万供应商是天然种子节点池
4. 建筑业年产值30万亿，1%效率提升=1500-2100亿
5. Google A2A 2025年4月发布，预计2027-2028年生产级稳定
6. 供应商ERP API化率是瓶颈，当前仅10-15%数字化率

#### 论据校验

| 论据 | 校验 | 详情 |
|------|------|------|
| 110万供应商 | ✅已验证 | 与SC-01/SC-03数据一致 |
| 供应商数字化率10-15% | ✅已验证 | 确实很低。**但也意味着Agent协同前提条件（系统API化）严重不足** |
| 1%效率提升=1500-2100亿 | ⚠️需补充 | "1%而非0.1%或5%"缺乏依据。建议引用Gartner/McKinsey关于B2B自动化的效率提升benchmark |
| A2A协议2027-2028成熟 | ⚠️需补充 | 从协议发布到生产级稳定通常需3-5年（参照HTTP/2、GraphQL）。**2027-2028过于乐观，2029-2030更现实** |
| Agent协商可靠性 | ❌存疑 | 报告承认"未到生产级"但未量化差距。LLM在"约束协商"（模糊约束下的决策）能力缺乏benchmark验证——**这是整个品类的核心技术假设** |
| Agent代签法律效力 | ⚠️需补充 | "AI Agent代为签署"的法律地位在中国法律框架下完全空白，可能需专门立法，时间线可能更长 |
| 网络效应先发锁定 | ⚠️需补充 | 供应商可能同时接入多个平台（类似淘宝+京东），网络效应强度可能被高估 |

#### 关键风险
- **核心技术假设缺乏验证**：Agent协商可靠性未提出验证方案，仅靠沙盒模拟不够
- **供应商数字化率10-15%是严重瓶颈**：85-90%供应商无法接入，即使Top 1000完成API化也仅覆盖不到1%
- **评分体系存在矛盾**：四维评分20.1分（加权百分制）vs 73分（原始评估），差异巨大易混淆
- **A2A时间线过于乐观**：如2029-2030才成熟，整个品类时间线应后移2年

#### 修改建议
1. 增加Agent协商能力benchmark验证：100个真实询价场景测试LLM响应质量
2. 重新评估供应商数字化率影响：如3年内仅5%完成API化，网络效应是否足够？
3. **统一评分口径**：明确四维评分20.1分与73分的关系
4. A2A时间线增加2年缓冲：2027-2028→2029-2030
5. 增加"供应商数据安全顾虑"分析：让Agent接入库存系统涉及商业机密

4. 评分修正：从原45分上调至62分，核心变化是②+④叠加效应和IS-B08地基拉动

#### 论据校验

| 论据 | 校验 | 详情 |

3. 补充国内区块链+建筑追溯实际案例

## 五、跨领域共性问题

### 1. 数据来源标注不规范
15份报告中，大量市场数据缺乏明确来源（680亿审图市场、107-127万亿AR、500亿意外险、3500亿机器人天花板等）。建议统一增加**数据来源标注规范**：每个关键数据必须附来源、年份、统计口径。

### 2. "入口竞争"分析系统性不足
- 软件：广联达bundle、新点软件系统嵌入、品览先发优势
- 硬件：海康/大华智慧工地产品线
- 平台型竞品的降维打击能力被普遍低估

### 3. 政策风险评估偏乐观
- 77号文"鼓励"非"强制"
- 政府定额体系退出周期远超预期
- 政府采购接受度不确定
- GDPR/PIPL合规被轻描淡写

### 4. 评分修正的"自引用循环"
FUT-E引用过时的IS-B08 87分做评分修正，而IS-B08实际已降至66分。建议建立**评分修正的溯源验证机制**：每次引用其他报告的评分时，必须核实该评分是否为最新版本。

### 5. 未来品类的前置条件脆弱性
3/5个未来品类的评分建立在低分前置品类的成功之上（58/46/66分），建议为每个未来品类增加**"前置条件失败"的备选路径分析**。
