# 知识库与 RAG（检索增强生成）

## 一句话定义

**RAG** 是让 AI 在回答问题时，先查你自己的资料库，再基于查到的内容作答的技术。它解决了 AI"不懂你公司的事"和"会瞎编"两大问题。

## 直观理解：给 AI 配一个专属图书管理员

想象一个场景：

```
你问 AI："我们公司的差旅报销标准是什么？"

没有 RAG 的 AI：
  → "一般企业差旅标准包括...（通用回答，可能和你公司规定不同）"

有 RAG 的 AI：
  → 先去你的公司制度文件里查
  → "根据《中建发展差旅管理办法》第3条规定：
     一类城市住宿标准500元/晚，二类城市350元/晚..."
```

| | 普通 AI | RAG 增强 AI |
|--|---------|------------|
| 知识来源 | 训练时的公开数据 | 你的私有文档 |
| 回答准确性 | 可能过时或编造 | 基于你的真实资料 |
| 隐私安全 | 数据上传到外部 | 本地处理，文档不出境 |
| 适用场景 | 通用问题 | 企业内规、项目资料、个人笔记 |

## RAG 工作流程

```
┌──────────────┐      ┌──────────────┐      ┌──────────────┐
│   你的文档    │  →   │   切片存储    │  →   │   向量数据库   │
│ (PDF/Word/   │      │ (切成小段落   │      │ (每段转成     │
│  Markdown)   │      │  + 编号)     │      │  数字向量)    │
└──────────────┘      └──────────────┘      └──────────────┘
                                                    ↑
                                                    │ 匹配
┌──────────────┐      ┌──────────────┐      ┌──────────────┐
│   AI 生成    │  ←   │   拼接提示    │  ←   │   检索相关    │
│   回答       │      │   "根据以下    │      │   段落        │
│              │      │   资料回答..."│      │               │
└──────────────┘      └──────────────┘      └──────────────┘
```

### 三步走

1. ** ingest（摄入）**：把文档切小块，转成向量存入数据库
2. ** retrieve（检索）**：用户提问时，找到最相关的文档片段
3. ** generate（生成）**：把检索到的片段 + 用户问题一起给 AI，让 AI 基于资料作答

## 知识库的两种形态

### 形态一：个人知识库（第二大脑）

目标：管理个人学习、工作、生活的知识资产。

```
个人知识库
├── 工作笔记（会议纪要、项目复盘、制度文件）
├── 学习笔记（读书摘要、课程笔记、行业报告）
├── 灵感记录（想法、金句、待办）
└── 输出归档（写过的报告、PPT、文章）
```

**核心价值**：
- 信息不再散落各处（微信收藏、邮件、笔记本）
- AI 能基于你的全部笔记回答"我去年关于XX项目是怎么做的"
- 知识产生复利：今天记的一条笔记，3 个月后可能帮上大忙

### 形态二：企业知识库

目标：沉淀组织知识，让新员工快速上手，让老员工高效查询。

```
企业知识库
├── 规章制度（人事、财务、行政制度）
├── 项目资料（方案、合同、会议纪要）
├── 培训材料（内部课程、操作手册）
├── 客户信息（客户需求、沟通记录）
└── 行业研究（竞品分析、政策解读）
```

**核心价值**：
- 新人 onboarding 从 3 个月缩短到 2 周
- 制度查询从"问同事"变成"问 AI"
- 项目经验不再随人员流动而流失

## Obsidian + Claude Code：构建个人知识库的最佳方案

### 为什么选择这个组合？

| 工具 | 作用 | 优势 |
|------|------|------|
| **Obsidian** | 笔记存储和管理 | 本地 Markdown，数据完全私有；双向链接；插件生态丰富 |
| **Claude Code** | AI 助手 | 直接读写本地文件；理解整个知识库；可自动化维护 |
| **Markdown** | 统一格式 | 纯文本、跨平台、永不过时、AI 友好 |

### 日常 workflow

```
1. 收集 → 随手把文章、想法丢进 00-Inbox
2. 整理 → 定期（如每周五下午）用 Claude Code 帮助分类、打标签
3. 连接 → 在笔记间建立双向链接 [[相关笔记]]
4. 输出 → 基于积累的知识写报告、做方案
5. 回顾 → 定期让 AI 总结"最近关于XX主题我记了哪些笔记"
```

## 常见误区

| 误区 | 真相 |
|------|------|
| "知识库就是存文件" | 不是。知识库的核心是**连接和提取**，存而不连是垃圾堆 |
| "AI 能帮我自动整理一切" | AI 能辅助，但架构设计和价值判断仍需人来做 |
| "建知识库需要会编程" | 不需要。Obsidian + Claude Code 的方案零代码即可 |
| "笔记越多越好" | 质量 > 数量。100 条精加工的笔记 > 1000 条随手复制的链接 |
