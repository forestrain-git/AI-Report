# AI战略选择框架

> 跳出具体项目，从最广义的维度回答一个问题：**一家组织"做AI"，有哪些大方向可选？不同流派怎么看？**
>
> 用途：帮助决策者在选择具体AI方向之前，先建立认知地图——知道有哪些选项、各有什么代价、谁主张什么。

---

## 核心判断

纵观所有流派，有一个正在形成的共识：

> **模型层正在快速商品化，数据和场景才是壁垒。**
>
> 但分歧在于：**这个"商品化"到了什么程度？你的组织应该站在哪一层？**

下面从七个维度展开，每个维度给出全景图谱+主要流派意见。

---

## 维度一：技术纵深 —— 做AI的"哪一层"？

### 全景图谱

```
 层级              做什么                        典型投入            壁垒来源
 ─────────────────────────────────────────────────────────────────────────────
 L0 算力层          建智算中心/芯片               十亿~百亿级          资本+政策
 L1 基座模型层      自研通用大模型（从零训练）      亿~十亿级            人才+算力
 L2 行业模型层      垂直领域精调/蒸馏/行业大模型   千万~亿级            行业数据
 L3 应用集成层      调用API+RAG+Agent编排          万~百万级            场景理解
 L4 工具消费层      直接使用现成AI工具（豆包等）    零成本               无壁垒
```

### 主要流派

#### 流派一：全栈自研派

**代表**：中石油昆仑大模型、国家电网光明大模型、中交蓝翼大模型
**主张**：央企必须掌握核心能力，从算力到模型到应用全栈自研。
**逻辑**："如果底层不在自己手里，关键时刻会被卡脖子。"（信创逻辑+自主可控逻辑）
**代价**：投入巨大（昆仑大模型3000亿参数，数十亿投入），且面对GPT/DeepSeek等通用模型的版本碾压——通用模型更新一次可能就覆盖你了。
**适用条件**：有足够资本、有足够算力、有足够人才、有足够数据。**全球范围内能干这件事的组织不超过50家。**

#### 流派二：开源精调派

**代表**：Hugging Face社区、Mistral、Meta Llama生态
**主张**：开源模型已经足够强，用开源基座+私有数据微调，效果不输闭源，成本低一个数量级。
**逻辑**：Meta的Llama、阿里的Qwen、DeepSeek等开源模型持续进步，闭源模型的领先窗口越来越短。用开源模型私有化部署，数据不出域，安全可控。
**代价**：需要一定的技术团队（能做Fine-tuning和部署），但远比自研基座轻量。
**适用**：**绝大多数行业企业的最佳选择。**

#### 流派三：API集成派

**代表**：吴恩达（Andrew Ng）、大部分初创公司
**主张**：不要训练模型。用现成API（DeepSeek/Qwen/Claude），配合RAG和Prompt Engineering，就能解决80%的问题。为了剩下20%的精度提升去自研模型，ROI为负。
**逻辑**：模型能力每年翻倍，你的Fine-tuning效果可能还不如一年后的基础模型。绑定在某个模型上反而是负资产。用API保持灵活性。
**代价**：可变成本高（按Token付费），数据安全和隐私有风险（需私有化部署方案）。
**适用**：**AI刚起步、验证阶段的组织。**

#### 流派四：小模型派

**代表**：Microsoft Phi系列、Google Gemma、学术界边缘计算流派
**主张**：大模型太贵太慢。用几十亿参数的小模型+蒸馏/量化技术，部署到端侧，成本低、速度快、数据安全。
**逻辑**：很多场景不需要千亿参数的能力。一个30亿参数的专用小模型在特定任务上可以超过GPT-4的准确率，而成本是千分之一。
**适用**：**硬件嵌入式场景、边缘计算场景、高并发低延迟场景。**

#### 流派五："模型即商品"派

**代表**：Sam Altman（OpenAI）、Andrej Karpathy
**主张**：模型本身会变成像电力一样的商品。未来的竞争不在模型层，而在应用层和数据层。
**逻辑**：OpenAI自己正在努力把模型做得又好又便宜，目标就是让模型成为基础设施。如果你在做模型，你是在和OpenAI/Google/Anthropic直接竞争——不是一个明智的选择。
**影响**：这个流派强有力地支持"不要自研模型，聚焦应用和数据"的结论。

---

### 对中建发展的意味

最务实的结论是 **L3（应用集成）为主 + L2（行业小模型）探索**：
- 不做L0/L1（不是建智算中心的，也没有自研通用大模型的必要）
- L2可以做垂直领域的蒸馏小模型（有行业数据的话）
- L3是主战场——用成熟大模型的能力，配上中建的行业数据和场景理解，做AI应用

## 维度二：商业角色 —— AI是你的什么？

### 全景图谱

```
角色        本质           财务属性        核心问题
──────────────────────────────────────────────────────────────
工具        AI帮你干活      成本中心        省了多少钱？
产品        AI就是你的货    利润中心        卖了多少钱？
能力        AI嵌入核心业务  竞争壁垒        别人多久追上？
战略        AI重新定义行业  赌注            不做会死吗？
```

### 主要流派

#### 流派一："AI作为工具"（Cost Center）

**代表**：McKinsey数字化咨询、大多数传统企业
**主张**：AI的首要价值是降本增效。不要想着用AI赚钱，先用AI省钱。
**典型指标**：人效比、流程耗时缩短百分比、错误率下降幅度。
**风险**：天花板低。省钱省到一定程度就停了，而且容易被竞争对手复制。
**适合**：AI刚起步、试水阶段。

#### 流派二："AI作为产品"（Revenue Center）

**代表**：SaaS公司、AI原生初创企业
**主张**：AI本身就是产品。卖API、卖SaaS、卖解决方案。
**典型指标**：ARR、客户数、毛利率。
**风险**：护城河难建。如果底层模型是别人的，你的产品壁垒在哪里？
**适合**：有独占数据或深度场景理解的组织。

#### 流派三："AI作为能力基础设施"（Capability Moat）

**代表**：特斯拉（FSD自动驾驶）、字节跳动（推荐算法）
**主张**：AI不是单独的产品，而是嵌入到核心产品中、让核心产品变得不可替代的能力。
**典型指标**：用户粘性、替代成本、数据飞轮转速。
**逻辑**：AI不是目的，是手段。但它是**别人抄不走的手段**。
**适合**：处于竞争激烈行业、需要用AI拉开差距的组织。

#### 流派四："AI作为平台"（Platform Strategy）

**代表**：Microsoft Copilot生态、字节跳动豆包
**主张**：AI成为所有产品的统一入口和交互方式。用AI锁定用户，建立生态。
**典型指标**：MAU、生态伙伴数、API调用量。
**风险**：平台战争赢家通吃，只有头部玩家能玩。
**适合**：已经有强大用户基础和技术能力的平台型企业。

#### 另一组重要分类：AI-Native vs AI-Added

这是硅谷投资圈常用的分法：

| | AI-Native（原生） | AI-Added（添加） |
|:---|:---|:---|
| 定义 | 第一天就AI驱动 | 现有产品+AI功能 |
| 建筑行业例子 | 用AI自动生成施工方案 | 现有项目管理软件加个AI助手 |
| 组织方式 | AI团队主导产品 | 现有产品团队加AI能力 |
| 风险 | 可能脱离真实需求 | 可能只是表面功夫 |
| 代表企业 | OpenAI、Anthropic | Microsoft、Salesforce |

**争议**：AI-Native派认为AI-Added只是"给马车装了个车灯"，真正的变革来自原生AI设计；AI-Added派认为在现有产品和流程上逐步叠加AI才是务实路径，直接原生重构风险太高。

## 维度三：策略节奏 —— 怎么进场？

### 全景图谱

```
                 激进                   平衡                  保守
                 ─────                 ─────                ─────
投入程度         大额投入               可控试点               观望等待
时间取向         先发制人               稳扎稳打               后发制人
风险管理         风险偏好               风险可控               风险规避
人才策略         高薪抢人               内部培养+外聘          外包为主
```

### 主要流派

#### 流派一：All-in 激进派

**代表**：Sam Altman、硅谷VC（a16z、Sequoia）
**主张**："AI的iPhone时刻已经到来，窗口期6-18个月。"要么All-in，要么被淘汰。
**逻辑**：技术变革的速度是指数的，线性思维的安全区域是错觉。大举投入可能失败，但不投入注定失败。
**风险**：可能烧了很多钱但方向不对。中石油昆仑大模型投了几十亿，但也有说法"效果还不如直接用GPT-4"。

#### 流派二：试点驱动派（吴恩达五步法）

**代表**：Andrew Ng、Google Brain方法论
**主张**：不要上来搞战略规划，先跑试点。选一个成功概率最高的小项目，6个月内出结果，用真实数据决定下一步。
**五步法**：试点项目 → 组建AI团队 → AI培训 → 制定AI战略 → 内外部沟通
**关键洞察**：战略是第四步，不是第一步。先搞清楚AI能做什么，再定战略。顺序错了，战略就是纸上谈兵。
**风险**：可能"试点成功但规模化失败"——局部能跑通不代表全组织能推。

#### 流派三：经典战略派（McKinsey/BCG）

**代表**：传统管理咨询
**主张**：先诊断、再规划、再执行。用完整的战略框架（如McKinsey的"AI转型八要素"）做系统评估，6-12个月出战略蓝图。
**批评**：被吴恩达派批评为"花6个月写一份报告，然后发现写报告的时候技术已经变了"。

#### 流派四：内部创业派

**代表**：Amazon的"两个披萨团队"、Google X Lab
**主张**：在组织内部设立独立的AI团队，像创业公司一样运作，有独立的预算和决策权，不受主业流程束缚。
**逻辑**：AI和传统业务的节奏完全不同。用主业的管理方式管AI团队，会把AI团队管死。
**风险**：独立团队可能和主业脱节，做的东西没人用。

#### 流派五：OODA循环派（军事思维）

**源自**：美国空军将军 John Boyd
**主张**：Observe（观察）→ Orient（判断）→ Decide（决策）→ Act（行动），比对手更快地跑完这个循环。
**应用到AI**：不要追求一次性做对，追求"比对手更快地试错、更快地学习"。小步快跑、快速迭代。
**好处**：天然适合AI这种快速变化的技术领域。

#### 流派六：杠铃策略（Taleb反脆弱）

**源自**：Nassim Taleb《反脆弱》
**主张**：把资源分成两极——极度保守（守住主业现金流）+ 极度激进（小赌注搏大机会）。不要走中间路线。
**应用到AI**：拿出90%的资源守住现有业务，拿出10%的资源押注几个激进的AI方向。赢了爆发，输了不影响生存。
**适合**：对风险敏感的大型组织。

### 几个实用的判断框架

#### "AI成熟度"自评（决定进场速度）

| 阶段 | 特征 | 推荐节奏 |
|:----|:-----|:---------|
| L1 认知期 | 领导不知道AI能做什么 | 先做培训，再跑1-2个极低成本试点 |
| L2 试点期 | 有零散试点，但没规模化 | 选1个方向深耕出案例，建立组织信心 |
| L3 建设期 | 有团队有试点，但没有明确战略 | 做3-6个月的系统研判，制定AI战略 |
| L4 规模期 | AI嵌入核心业务流程 | 加大投入，建立数据飞轮，考虑对外输出 |
| L5 引领期 | AI成为核心竞争力 | 全栈投入，探索行业级AI基础设施 |

#### "风险-回报"四象限

```
           回报高
             │
    █ 观望会死  │  █ 应该All-in
    (行业颠覆中) │  (有独占数据+场景)
    ────────────┼────────────
    █ 不做也罢  │  █ 试点即可
    (风险低机会也低)│ (有机会但要验证)
             │
           回报低
   风险低←─────┼──────→风险高
```

## 维度四：人才组织 —— 怎么建团队？

### 全景图谱

```
集中度 ←─────────────────────────→ 分散度

AI CoE          Hub-and-Spoke     Federated          Embedded
┌────────┐     ┌────────┐        ┌────────┐        ┌────────┐
│ 所有AI  │     │中央团队│        │中央定标准│        │AI人直接 │
│人才集中 │     │+业务对接│        │各业务自跑│        │在各业务线│
│一个部门 │     │  人    │        │        │        │        │
└────────┘     └────────┘        └────────┘        └────────┘
```

### 主要流派

#### 流派一：AI Center of Excellence（AI卓越中心）

**代表**：大多数央企、金融机构初期的选择
**做法**：所有AI人才集中在一个部门，统一服务全公司。
**优点**：人才集中、知识沉淀、避免重复造轮子。
**缺点**：容易脱离业务一线，做出没人用的AI产品。
**适用**：AI刚起步、人才稀缺的阶段。

#### 流派二：Hub-and-Spoke（中心+辐射）

**代表**：吴恩达推荐、Google、Microsoft
**做法**：中央AI团队（Hub）维护核心能力（模型、工具链、最佳实践），业务单元（Spoke）有AI对接人，通过矩阵式协作。
**优点**：兼顾集中效率（避免重复造轮子）和业务贴近（避免脱离需求）。
**缺点**：需要较强的跨部门协调能力。
**适用**：多业务线、需要统一技术底座的组织。

#### 流派三：Federated（联邦模式）

**代表**：Amazon（两个披萨团队文化）
**做法**：中央只定标准和工具链（"护栏"），各业务线自己招AI人、自己跑项目。中央确保各业务线不会走偏，但不干预具体执行。
**优点**：极度灵活，业务线自主权大。
**缺点**：可能形成知识孤岛，人才流失风险高。
**适用**：业务线独立性强、数字化成熟度高的组织。

#### 流派四：Embedded AI（嵌入式）

**代表**：成熟科技企业
**做法**：没有单独的"AI部门"，AI人直接嵌入各个业务产品团队。
**优点**：最贴近业务，AI和产品结合最紧密。
**缺点**：AI人才在每个团队里可能很孤单，没有peer learning。
**适用**：AI能力已经比较成熟的组织。

#### 流派五：混合模式（Hybrid）

**代表**：大多数企业在成熟期的选择
**做法**：初期用CoE集中起步，逐步过渡到Hub-and-Spoke，成熟期转向Federated/Embedded。
**路径**：集中→hub-and-spoke→分散。这是一个演进过程，不是一次性选择。

---

### 几个关键争议

**自建团队 vs 外包合作**

| 方式 | 优点 | 缺点 |
|:----|:----|:----|
| 全自建 | 能力内化，长期壁垒 | 慢、贵、难招人 |
| 全外包 | 快、灵活 | 做完了人走了，积累不了能力 |
| 合作自建 | 外部专家带内部团队 | 需要管理好知识转移 |
| 平台依赖 | 用建证大模型等现成平台 | 能力天花板受限于平台 |

**知识储备：AI人才从哪来？**

- **招外部专家**（贵，存在文化适配问题）
- **内部转型**（原有IT人员学习AI，慢但稳定）
- **应届生培养**（周期长，但可塑性强）
- **混合路径**（少量核心岗位招外部专家+大量原有团队转型）

当前（2026年）AI人才市场的现实：

> 头部AI人才年薪几百万甚至上千万，央企在薪酬上很难和互联网/初创公司竞争。务实策略是：核心岗位（模型训练、架构设计）用少量外部专家，大量应用层工作通过内部IT人员转型+AI工具提效（如Claude Code等AI编程工具）来弥补。

## 维度五：数据战略 —— 护城河有多深？

### 数据层次

```
层次               含义                   壁垒强度
──────────────────────────────────────────────────
独占数据           只有你有                极高（不可复制）
半独占数据         你有但别人也能慢慢拿    中等（先发优势）
公开数据           谁都能拿到              无（没有壁垒）
合成数据           自己生成                弱（需验证可靠性）
无数据             啥都没有                别做AI了
```

### 主要流派

#### 流派一：Data-Centric AI（以数据为中心）

**代表**：Andrew Ng、李飞飞
**主张**：模型是 commodity，数据才是稀缺品。提升数据质量比调模型参数更重要。"用更好的数据训练同样的模型，效果超过用同样的数据训练更好的模型。"
**实践**：数据清洗、标注质量、数据增强、数据治理。
**对央企的意义**：你们有数据，但数据质量可能很差。清洗+治理比找新模型更重要。

#### 流派二：数据飞轮派（Data Flywheel）

**代表**：字节跳动、所有平台型企业
**主张**：AI的核心优势不是静态的数据量，而是数据循环的速度。好产品→更多用户→更多数据→更好的AI→更好产品，形成正循环。
**关键**：闭环反馈——用户的使用数据要能回流到模型训练中，让模型越来越好。
**对央企的意义**：很多央企的AI产品没有数据回流机制（陶锋在录音里也说过这个问题），产品上线后就停了，没有形成飞轮。

#### 流派三：合成数据派

**代表**：Google DeepMind、微软
**主张**：真实数据快用完了，未来AI训练主要靠合成数据（AI生成的数据再用来训练AI）。
**逻辑**：GPT-5/6的训练已经大量使用合成数据。在某些垂直领域，合成数据+少量真实数据的效果已经超过纯真实数据。
**争议**：有批评认为合成数据会导致"模型自噬"（Model Collapse）——用AI生成的数据训练AI，模型的多样性会逐代下降。

#### 流派四：数据主权派

**代表**：中国政府、欧盟GDPR、信创体系
**主张**：数据是战略资源，不能出境。必须本地化存储、本地化处理、本地化训练。
**对央企的影响**：这是硬性要求，不是选择。央企的AI系统必须满足数据安全合规、等保三级、信创适配等要求。这意味着不能用境外云服务训练央企的敏感数据。

#### 流派五：最小数据派

**代表**：小样本学习（Few-shot Learning）、RAG社区
**主张**：不需要海量数据。用大模型的few-shot能力+RAG（检索增强生成），只需要少量高质量样本就能达到不错的效果。
**对央企的意义**：你不需要把十年积累的100万份合同全部拿去训练模型。先挑1000份高质量样本，配合RAG做检索，就能解决大部分问题。**数据门槛没有你以为的那么高。**

## 维度六：部署方式 —— 云还是端？

### 全景图谱

```
纯云端 ──────── 混合 ──────── 纯本地 ──────── 端侧
按Token付费     敏感数据本地    全部私有化     嵌入式芯片跑模型
  + 通用计算       + 非敏感上云     + 数据不出域     + 离线可用
  + 起步快         + 成本适中       + 最安全         + 零延迟
  - 数据安全风险   - 架构复杂       - 投入大         - 模型能力受限
  - 长期成本高                     - 更新慢
```

### 主要流派

#### 流派一：公有云优先派

**代表**：阿里云、华为云、AWS
**主张**：用云服务，按量付费，保持灵活性。大模型的API调用速度和能力迭代远超私有化部署。
**央企困境**：数据安全要求使得很多场景不能上云。但非敏感场景（办公提效、公文写作）完全可以用云服务。

#### 流派二：私有化部署派

**代表**：华为Stack、信创厂商
**主张**：央企的数据不能出域。必须私有化部署，用开源模型+国产硬件（昇腾等）。
**代价**：投入大、更新慢、模型能力落后于云端最新版本。

#### 流派三：混合派（当前实事上的主流）

**做法**：敏感业务私有化部署（供应链数据、招投标数据），非敏感业务用云服务（办公辅助、会议纪要、公文写作）。
**趋势**：2026年，这种分层部署已经成为央企的主流选择。不是说"要么上云要么私有"，而是**按数据敏感度分层**。

#### 流派四：边缘AI派（Edge AI）

**代表**：Apple Intelligence、高通、ESP32生态
**主张**：AI最终要跑在端侧——手机、IoT设备、安全帽、摄像头。推理在本地完成，不上云。
**好处**：零延迟、数据不出设备、离线可用。
**局限**：端侧模型能力受限，不适合复杂推理任务。
**对中建发展的意义**：AI安全帽就是典型的边缘AI场景——识别在安全帽端完成，不上云。

## 维度七：时代选择 —— 2026年的特殊约束

以上六个维度是普适的，但2026年的中国央企在以上所有维度上还有一层额外约束：

### 约束一：信创（国产替代）

**所有AI系统必须满足国产化要求**：
- 硬件：优先用昇腾/寒武纪等国产芯片
- 模型：优先用DeepSeek、Qwen、文心一言等国产大模型
- 框架：优先用MindSpore、PaddlePaddle等国产框架
- 应用：必须能适配国产操作系统

### 约束二：合规红线

- 境外AI服务不能直接用于处理内部敏感数据（需数据脱敏或私有化部署）
- 生成式AI内容必须有标识
- AI系统须通过等保三级
- 数据分类分级管理

### 约束三：国资委考核

- AI应用纳入央企经营业绩考核
- 场景培育、AI投资、人才建设都是考核指标
- "不做"的代价不仅是落后，还是考核失分

### 约束四：集团统一底座

中建集团已经统一建设了建证大模型平台，子企业原则上在集团底座上做应用开发，不能各自建独立算力。

## 将这些维度整合成一个决策框架

当被问到"我们该做什么AI"时，用这个顺序梳理：

```
第一步：定位 —— AI在这个组织里扮演什么角色？
  工具（降本） → 产品（创收） → 能力（壁垒） → 战略（重构）
                          ↓
第二步：纵深 —— 做哪一层？
  算力层 → 基座模型层 → 行业模型层 → 应用集成层 → 工具消费层
                          ↓
第三步：数据 —— 有什么数据？数据质量如何？能否形成飞轮？
  独占数据 > 半独占 > 公开数据 > 合成数据 > 无数据
                          ↓
第四步：节奏 —— 当前处于什么阶段？应该怎么进？
  L1认知期 → L2试点期 → L3建设期 → L4规模期 → L5引领期
                          ↓
第五步：组织 —— 怎么搭团队？
  CoE → Hub-and-Spoke → Federated → Embedded（演进路径）
                          ↓
第六步：部署 —— 数据敏感度决定部署方式
  纯云端 ↔ 混合 ↔ 私有化 ↔ 端侧
```

**底层逻辑**：六个步骤中，**第一步（定位）决定后面所有选择**。定位没想清楚，后面每一步都会反复横跳。
