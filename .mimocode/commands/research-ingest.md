# 研究 & 纳入知识库

针对指定主题进行全网搜索，提炼关键信息后写入 wiki 知识库。

## 输入

`$ARGUMENTS` — 研究主题 + 需要搜索的维度列表。

示例：
```
中建发展 AI 软硬件方向
- 维度1：政策锚定（两会、国资委文件）
- 维度2：技术祛魅（大模型、Agent、RAG 解释）
- 维度3：同行压力（全球建筑企业 AI 案例）
- 维度4：中建系统内案例
```

## 执行步骤

### Phase 1：规划搜索任务

1. 读取 `wiki/index.md` 了解已有知识
2. 对比用户要求的维度，识别已有 vs 缺失
3. 为每个缺失维度创建一个搜索子任务

### Phase 2：并行搜索

为每个维度分派子代理（subagent）：

```
每个子代理的任务：
1. 使用 web-access 技能搜索该维度的信息
2. 要求：有官方出处、有说服力、最新（2024-2026）
3. 输出：结构化 markdown 摘要，包含来源链接
```

并行度建议：
- 3-5 个维度 → 3-5 个子代理并行
- 每个子代理搜索 5-10 个高质量来源

### Phase 3：提炼入库

收集所有子代理结果后：

1. **创建来源摘要** → `wiki/sources/摘要-来源-主题.md`
   - YAML frontmatter：title, type=source, tags, sources, last_updated
   - 一句话核心主旨
   - 关键数据点（带出处）
   - 关联连接 `[[wikilink]]`

2. **更新/创建实体** → `wiki/entities/实体名称.md`
   - 如果新发现的实体（公司、人物、产品）在 wiki 中不存在，创建实体页
   - 如果已存在，更新相关区块

3. **更新/创建概念** → `wiki/concepts/概念名称.md`
   - 政策文件、技术概念等

4. **更新综合分析** → `wiki/synthesis/分析主题.md`
   - 如果有跨实体的分析价值，创建或更新综合分析页

5. **更新 index.md** → 将新页面加入目录

6. **追加 log.md** → 记录本次 ingest 操作

### Phase 4：输出报告

向用户汇报：
- 搜索了哪些维度
- 发现了哪些新实体/概念
- 更新了哪些现有页面
- 建议的后续讨论方向

## 知识库规范提醒

- `/raw/` 绝对只读，不修改
- 每个 wiki 页面必须有 `## 关联连接` 区域
- 实体用 TitleCase 命名，来源摘要用 kebab-case
- 矛盾信息保留两种说法，新建 `## 知识冲突` 区块
- 脚注中涉及知识库内容写"小组调研"
